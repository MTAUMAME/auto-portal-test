## 1. Next.jsの肝：「UIをツリーに分解する」とは？

Next.js（特にApp Router）では、1つの画面（ページ）をバラバラの「パーツ（コンポーネント）」に分解し、それらが親子関係を持つ**「UIツリー」**として捉えます。

### なぜツリーに分解するのか？
最大の理由は、**「React Server Components (RSC)」**と**「Client Components (RCC)」**を最適に配置するためです。

```
[ Root Layout (Server) ]
       │
       ├─ [ Header (Server) ]
       │     └─ [ SearchBar (Client: 動きがある) ]
       │
       └─ [ Main Page (Server) ]
             ├─ [ Product List (Server: データベースから直接取得) ]
             └─ [ Like Button (Client: クリックで状態変化) ]
```

*   **サーバーコンポーネント（Server）：** データを直接取得する、重い処理を行う（ツリーの「根本」に配置するのが基本）。
*   **クライアントコンポーネント（Client）：** ボタンのクリックやアニメーションなど、ブラウザ側でのインタラクションが必要な部分（ツリーの「末端」に局所化する）。

**【鉄則】** 
「全部Client Component（`"use client"`）」にするのはNG。**可能な限りツリーの上位をServerにし、動きが必要な末端だけをClientに分解する**ことで、ページ読み込み速度（LCP）が爆発的に向上します。
