# 【結論】Claude Codeを「放置プレイ」するならDocker Sandboxesが現代の最適解

AnthropicがリリースしたCLIツール「Claude Code」は、ターミナル上で爆速でコードを書き、テストを回し、バグを修正してくれる最高のAIパートナーです。

しかし、Claude Codeの真価を発揮する**「オート承認モード（`--dangerously-skip-permissions`）」**を使う際、こんな恐怖を感じたことはありませんか？

> **「間違えて重要なローカルファイルを削除されたらどうしよう…」**
> **「環境変数のAPIキーが漏洩したり、勝手に変な外部通信をされたら…？」**

この「便利さと危険のトレードオフ」を鮮やかに解決するのが**Docker Sandboxes（サンドボックス環境）**です。

---

## 1. YamaC氏の記事要約：なぜ「Docker Sandboxes一択」なのか？

記事の核心は**「安全性を担保した上での完全自動化」**にあります。

### 主なポイント
1. **Claude Codeの「自走」にはリスクが伴う**
   権限チェックを毎回手動で押していてはAIエージェントのスピード感が活きない。しかし、無制限の実行権限をローカル環境に与えるのはセキュリティリスクが高すぎる。
2. **従来のDockerだとセットアップやファイル同期が面倒**
   通常のDockerコンテナでも隔離は可能だが、ローカルファイルとの同期（ボリュームマウント）や権限設定、環境変数の受け渡しなど、環境構築の手間（オーバーヘッド）が大きい。
3. **Docker Sandboxes（MicroVM等）の衝撃**
   Docker公式やサードパーティが提供する最新のサンドボックス技術を使えば、**「ローカル並みの使い勝手」と「完全な仮想化による隔離性」を両立**できる。
4. **結論**
   「Claude Codeに全自動でコードを書かせて自分は寝る」という運用（自走）をするなら、インフラ設定のコストと安全性のバランス的に「Docker Sandboxes」を選ぶのが最もスマートである。

---

## 2. 徹底比較！ローカル直・従来Docker・Docker Sandboxes

Claude Codeを実行する3つの環境について、コスト・パフォーマンス・安全性を表にまとめました。

| 比較項目 | ① ローカル直実行 | ② 従来のDocker | ③ Docker Sandboxes (推奨) |
| :--- | :--- | :--- | :--- |
| **安全度（隔離性）** | ❌ 危険（PC全体が対象） | ⭕️ 高い | **数値：100%（完全隔離）** |
| **自走のしやすさ** | ⭕️ 爆速（ただし恐怖あり） | 🔺 設定次第で詰まる | **数値：極めてスムーズ** |
| **起動スピード** | 即時（0秒） | 2〜5秒 | **1〜3秒（MicroVM並み）** |
| **ファイル同期** | シームレス | 速度低下の可能性あり | **最適化されており快適** |
| **メモリ/CPU負荷** | 最小 | 中程度 | **中程度（8GB〜16GB推奨）** |
| **月額費用** | **0円** | **0円〜** | **0円〜（個人利用は基本無料）** |

### 性能面での解説
Docker Sandboxesは、従来の重い仮想マシン（VM）とは異なり、軽量なMicroVM技術などをバックエンドに使用しているため、**「安全なのに重くない」**のが最大の特徴です。Claude Codeが生成したコードのテスト実行も、ローカルとほぼ変わらないレスポンスで処理されます。
