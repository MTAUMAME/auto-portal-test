## 1. Aurora DSQLとは？（2026年の現状）

Amazon Aurora DSQLは、**PostgreSQL互換の、完全にサーバーレスな分散SQLデータベース**です。

最大の特徴は、**「複数リージョンにまたがるアクティブ・アクティブ構成」**を、複雑なレプリケーション設定なしで実現できる点。どこから書き込んでも、ミリ秒単位で同期されます。

### Rails開発者が2026年にDSQLに注目すべき理由
これまでRailsでマルチリージョン展開を行う場合、データベースの遅延（レイテンシー）や書き込み競合（コンフリクト）の解決に多大な血を吐くような努力が必要でした。
Aurora DSQLは、ActiveRecordの標準的な書き方のまま、グローバルスケールの恩恵を受けられる「銀の弾丸」として注目されています。

## 2. 性能・価格比較表（DSQL vs Aurora v2 vs RDS）

2026年現在のスペックと価格感をもとに、Railsアプリでよく使われる3つの構成を比較しました。

| 項目 | **Aurora DSQL** (2026最新) | **Aurora Serverless v2** | **RDS for PostgreSQL** |
| :--- | :--- | :--- | :--- |
| **アーキテクチャ** | 分散アクティブ・アクティブ | プライマリ＋リーダー (シングル書込) | シングルインスタンス (マルチAZ) |
| **接続数制限** | **実質無制限** (Connection Pool不要) | ACUに依存 (制限あり) | インスタンスサイズ依存 (要PgBouncer) |
| **マルチリージョン** | 標準機能 (自動同期・超低レイテンシー) | Global Database (レプリカ遅延あり) | 手動構築が必要 (難易度高) |
| **読み書きレイテンシー** | 1桁〜10ms台 (分散処理による) | 1〜5ms (単一ノード内なら最速) | 1〜5ms |

### 比較のポイント：
* **Aurora DSQLは「使った分だけ」の完全従量制。** アクセスが全くない夜間は、ストレージ料金（数十円レベル）しかかかりません。
* **コネクション数制限からの解放：** Railsの弱点だった「DB接続の枯渇問題」が、DSQLのプロキシレス接続によって過去のものになりました。

## 4. RailsアプリにAurora DSQLを導入する際の手順＆Tips

もし、あなたのRailsアプリに導入するなら、以下の3点は必須の設定です。

1. **主キーをUUID（特にUUIDv7）にする**
   分散データベースで連番（1, 2, 3...）を使うと、特定のノードに書き込みが集中（ホットスポット化）します。Rails 8以降標準のUUIDv7などを活用しましょう。
2. **N+1クエリの徹底排除**
   分散SQLはネットワークを跨ぐため、細かなクエリを大量に発行する「N+1問題」が発生すると、通常のRDS以上にパフォーマンスが劣化します。`Bullet`ジェムなどで事前に対策を。
3. **ローカル開発環境との差異吸収**
   ローカルはDockerのPostgreSQL、本番はDSQLとする場合、DSQL特有の機能制限（一部のニッチなPostgreSQL拡張機能が未対応）に引っかからないか、CI/CDで互換性をテストしましょう。
