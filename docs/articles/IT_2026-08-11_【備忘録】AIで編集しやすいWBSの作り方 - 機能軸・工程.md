## 1. 話題のQiita記事まとめ：AIと相性抜群の「Markdown WBS」とは？

元のQiita記事で紹介されているのは、**「ChatGPTなどのAIに、崩さずに編集・計算させやすいMarkdown形式のWBSテンプレート」**です。

通常、ExcelやスプレッドシートのWBSはAIに読み込ませづらく、出力時にセルが崩れてしまいがちです。しかし、**Markdown（マークダウン）形式**で以下のように設計することで、AIが劇的に扱いやすくなります。

### 💡 キーポイント：機能軸と工程軸の二軸管理
この手法の画期的な点は、WBSのタスクを「機能（何を作るか）」と「工程（どう作るか）」の2つの軸で整理し、**工数を自動集計（シミュレーション）させやすい構造**にしている点です。

#### 【Markdown WBS テンプレート例】
```markdown
| 機能ID | 機能名 | 工程 | 担当 | 予定工数(h) | 進捗率 | 備考 |
| :--- | :--- | :--- | :--- | :---: | :---: | :--- |
| F01 | ログイン画面 | 要件定義 | 山田 | 4 | 100% | |
| F01 | ログイン画面 | 実装 | 佐藤 | 8 | 50% | |
| F02 | マイページ | 実装 | 佐藤 | 12 | 0% | |
| F02 | マイページ | テスト | 鈴木 | 6 | 0% | |

### 【集計：機能軸】
- F01（ログイン画面）：12h
- F02（マイページ）：18h

### 【集計：工程軸】
- 要件定義：4h
- 実装：20h
- テスト：6h
```

### なぜこの形がAIに最適なのか？
1. **構造がシンプル：** AIが表のヘッダー（列名）を正確に認識できる。
2. **集計の指示がしやすい：** 「上記テーブルを元に、工程軸での合計工数を計算して」と指示するだけで、AIが正確に計算（ハルシネーションを防止）してくれる。
3. **コピペで即移行：** チャット画面とテキストエディタ（NotionやVSCode）の間をストレスなく行き来できる。
