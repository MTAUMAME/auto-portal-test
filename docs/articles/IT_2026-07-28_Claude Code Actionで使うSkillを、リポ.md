# 【GitHubクリーン化】Claude Code ActionのSkillをリポジトリにコミットせず『gh skill install』で動的導入する方法

![AI Coding Header](https://images.unsplash.com/photo-1618401471353-b98aedd07871?auto=format&fit=crop&w=1200&q=80)

現在、ターミナル上で自律的にデバッグやコード生成を行ってくれる「**Claude Code**」をCI/CD（GitHub Actions）に組み込み、自動コードレビューや自動修正を行わせる開発者が急増しています。

しかし、Claude Codeに特定の動作（Skill）を追加する際、**「Skillのコードをリポジトリ内に直接コミットしなければいけない」**という問題がありました。これにより、リポジトリが汚れたり、複数のプロジェクトで同じSkillを使い回すのが面倒になるというデメリットが発生します。

この課題をエレガントに解決したのが、技術ブロガーのshibayu36氏。今回はそのスマートな解決策を詳しく解説します。

---

## 1. 記事の要約：リポジトリを汚さない「実行時インストール」

通常、Claude Code ActionでカスタムSkillを使う場合、以下のようにリポジトリ内にファイルを置く必要がありました。

```text
.claude/
  └── skills/
        └── custom-skill.js  <-- これをコミットしたくない！
```

### 解決策：`gh skill install`（GitHub CLI）をワークフロー内で実行する

shibayu36氏が提案する手法は、**GitHub Actionsのワークフロー実行時に、GitHub CLIを使って動的にSkillをインストールする**という方法です。

#### メリット
1. **リポジトリがクリーンに保たれる**: 余計な設定ファイルやスクリプトをコミットする必要がありません。
2. **Skillの共通化・一元管理**: 別のリポジトリで管理している共通のSkillを、必要な時だけ呼び出して使えます。
3. **セキュリティの向上**: 共通のSkillリポジトリ側でアップデートを行えば、全プロジェクトに自動で反映されます。

#### 具体的な実装イメージ（GitHub Actions YAML）

```yaml
- name: Install Claude Code & Tools
  run: |
    npm install -g @anthropic-ai/claude-code
    # GitHub CLIを使って、別リポジトリで管理しているSkillを動的にインストール
    gh release download -R your-org/claude-skills -p "my-skill.js" -O .claude/skills/my-skill.js
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

このように、ワークフローのステップ内で一時的にディレクトリを作成してSkillをダウンロード（配置）することで、リポジトリを汚さずに任意のカスタム動作を実行時だけ組み込むことが可能になります。

## 2. 性能・価格比較：Claude Code vs 主要AIコーディングツール

AIを活用したコーディング支援ツールが群雄割拠する現在、どれを選ぶべきでしょうか？ 
「Claude Code（API課金）」と、代表的な「Cursor」「GitHub Copilot」を比較しました。

| ツール名 | Claude Code | Cursor (Pro) | GitHub Copilot |
| :--- | :--- | :--- | :--- |
| **開発元** | Anthropic | Anysphere (Cursor) | GitHub / Microsoft |
| **主な形態** | ターミナル（CLI）/ エージェント | エディタ（VS Codeフォーク） | エディタ拡張機能 |
| **料金体系** | **完全従量課金**（API利用料）<br>（目安：$10〜$50/月 ※使用量による） | **月額 $20** （定額制） | **月額 $10**（定額制） |
| **AIモデル** | Claude 3.5 Sonnet | GPT-4o, Claude 3.5 Sonnet 等 | Copilot独自の最適化モデル |
| **最大の特徴** | ターミナル上で自律的に動き、コマンド実行やテスト確認まで自動で行う | 高機能エディタ一体型で、コード全体のコンテキスト理解が最強 | エディタ内での補完速度が最速。安価で導入が容易 |
| **Skill/拡張性** | **高い**（カスタムSkillやMCPで無限に拡張可能） | 普通（VS Codeのプラグインに依存） | 低い（基本は補完とチャットのみ） |

### 比較のポイント
* **手軽さとコスト管理なら「Cursor」か「GitHub Copilot」**: 定額制なので使いすぎによる請求の心配がありません。
* **自律性と自動化の限界突破なら「Claude Code」**: API課金ですが、今回紹介した「GitHub Actionsでの自動化」など、開発プロセスそのものをAIに丸投げするレベルの自動化が可能です。
