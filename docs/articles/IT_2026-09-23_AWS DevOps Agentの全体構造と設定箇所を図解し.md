## 1. 5分でわかる「AWS DevOps Agent」全体構造と設定箇所（図解）

DevelopersIOの記事で紹介された、AWSの生成AIを活用したDevOpsエージェント（主にAmazon Q Developer / Bedrock Agentsを想定）の全体構造をシンプルに図解しました。

### 【全体構造図】
```text
[ 開発者 (IDE / AWS Console) ]
       │
       ▼ (1) 自然言語での指示 (例:「CI/CDパイプラインのバグを修正して」)
 ┌────────────────────────────────────────────────────────┐
 │ Amazon Q Developer Agent (DevOps Agent)                 │
 │                                                        │
 │  ┌─────────────────┐      (2) 推論      ┌────────────┐ │
 │  │  Orchestration  │ ◄────────────────► │  LLM Engine│ │
 │  │  (エージェント)  │                    │(Claude 3.5)│ │
 │  └────────┬────────┘                    └────────────┘ │
 └───────────┼────────────────────────────────────────────┘
             ▼ (3) アクション実行
 ┌────────────────────────────────────────────────────────┐
 │ AWS 環境 / 開発リポジトリ                              │
 │                                                        │
 │  ┌──────────────┐    ┌──────────────┐    ┌──────────┐  │
 │  │  AWS Lambda  │ ──►│  CodeCommit  │ ──►│ S3 Bucket│  │
 │  │ (API実行/評価)│    │ (コード修正)  │    │(ログ保管)│  │
 │  └──────────────┘    └──────────────┘    └──────────┘  │
 └────────────────────────────────────────────────────────┘
```

### 【重要な3つの設定箇所】
AWS DevOps Agentを正しく動かすためには、以下の3セクションの設定が肝となります。

1. **IAMロールと権限（Security & Governance）**
   * エージェントがAWSリソース（Lambda、CodePipelineなど）を操作するための「最小特権」を定義する場所。ここを間違えるとセキュリティホールになるか、エージェントが動きません。
2. **アクション・グループ（Action Groups）**
   * エージェントが「実際に何ができるか」を定義する設定。OpenAPIスキーマ（Swagger）とAWS Lambdaを紐付けることで、AIが自律的にAPIを実行できるようになります。
3. **ナレッジベース（Knowledge Bases）**
   * 社内ドキュメントやAWSのベストプラクティス（S3内のPDFやMarkdown）をAIに読み込ませる設定。これを行うことで、一般的な回答ではなく「自社専用のDevOps回答」が可能になります。
