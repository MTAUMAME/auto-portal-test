## 1. なぜ「標準CSS」は美しく、強力になったのか？

かつて標準CSSは、「ネスト（入れ子）が書けない」「変数管理が面倒」「ベンダープレフィックスが必要」など、多くの不満を抱えていました。そのため、SassやTailwind CSSなどのツールが必要不可欠でした。

しかし、現在のモダンCSSは以下の機能を**ネイティブでサポート**しています。

*   **CSS Nesting（ネイティブネスト）**: Sassのように、CSS単体で入れ子構造が書けるように（ブラウザ対応率95%以上）。
*   **CSS Variables（カスタムプロパティ）**: `var(--main-color)` で動的な一括管理が可能。
*   **`:has()` セレクタ（親子関係の制御）**: 「特定の要素を持つ親要素」のスタイル変更がJSなしで可能に。
*   **Container Queries（コンテナクエリ）**: 画面幅ではなく、親要素の幅に応じたレスポンシブデザイン。
*   **CSS Grid / Flexboxの成熟**: より直感的で美しいレイアウトが1行で可能。

**「Tailwindの独自クラス（`flex items-center justify-between p-4 bg-white rounded-lg shadow-md`等）を覚えるくらいなら、進化した標準CSSを書いた方が綺麗で早い」**という時代が到来したのです。

## 2. 【徹底比較】標準CSS vs Tailwind CSS

「導入コスト（学習・開発環境）」と「性能（表示速度・保守性）」の観点から両者を比較します。

| 比較項目 | 進化した標準CSS (Modern CSS) | Tailwind CSS |
| :--- | :--- | :--- |
| **初期費用 / ツール料金** | **完全無料**（ブラウザ標準） | **完全無料** |
| **学習コスト（価格換算）** | **極めて低い**（標準仕様のみ） | **中〜高**（独自のクラス名を覚える必要あり） |
| **環境構築の手間** | **ゼロ**（HTMLとCSSファイルを作るだけ） | **必要**（Vite, PostCSSなどの設定が必要） |
| **描画パフォーマンス** | **最高**（ビルド不要、ブラウザが直接解釈） | **高い**（未使用CSSは削除されるがビルドが必要） |
| **HTMLの可読性** | **美しい**（クリーンなHTMLを維持） | **最悪**（クラス名でHTMLがスパゲティ化する） |
| **AIとの相性** | **超優秀**（AIは標準CSSの記述が一番得意） | **普通**（プロンプトにコツが必要な場合も） |
| **寿命（将来性）** | **半永久的**（Web標準規格のため廃れない） | **トレンド依存**（数年後にレガシー化の懸念） |

### 性能（パフォーマンス）の裏側
Tailwindは「ビルド時に未使用のCSSをカットする（Purge）」ため軽量と言われますが、そもそも標準CSSをコンポーネント単位で適切に設計すれば、ビルドプロセス自体が不要になり、開発サーバーの起動も爆速（0秒）になります。

> 「既存のTailwindコンポーネント集（Tailwind UIなど）をコピペして爆速でLPを作りたい時は、やっぱりTailwindが手放せない。」（20代・フリーランスWeb制作）
