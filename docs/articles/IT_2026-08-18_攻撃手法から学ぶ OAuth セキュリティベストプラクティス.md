## 1. 攻撃手法から学ぶ！OAuth 3つの脆弱性と対策

OAuth 2.0の実装ミスを狙った代表的な3つの攻撃手法と、その防御策（ベストプラクティス）を解説します。

### ① 認可コード横取り攻撃 (Authorization Code Interception Attack)
*   **攻撃手法**: モバイルアプリやSPA（Single Page Application）において、悪意ある別アプリが「認可コード」を横取りし、被害者になりすましてアクセストークンを取得します。
*   **対策 (ベストプラクティス)**: **PKCE (Proof Key for Code Exchange) の必須化**。
    *   OAuth 2.1では、モバイルアプリだけでなく**すべてのクライアントでPKCEの使用が推奨（実質必須化）**されています。

### ② リダイレクトURIの検証不備 (Open Redirector)
*   **攻撃手法**: 認可サーバーがリダイレクトURI（`redirect_uri`）を前方一致などで曖昧に検証している場合、攻撃者はパラメータを書き換えて、トークンを悪意あるサイトに送信させます。
*   **対策 (ベストプラクティス)**: **完全一致（Exact Match）での検証**。ワイルドカード（`*`）の使用は絶対に避けてください。

### ③ CSRF（クロスサイトリクエストフォージェリ）によるアカウント連携強要
*   **攻撃手法**: 攻撃者が自身のSNSアカウントと、被害者のサービスアカウントを勝手に紐付け、被害者のデータにアクセスします。
*   **対策 (ベストプラクティス)**: **`state` パラメータの使用**、またはPKCEの導入（PKCEはCSRF対策としても機能します）。
