## 1. なぜ「Gemini × Claude」なのか？ハイブリッド運用の仕組み

結論から言うと、このシステムは**「Geminiに一次情報（大量の音声データ・テキスト）を処理させ、Claudeに極上の要約（人間基準のアウトプット）を作らせる」**という役割分担で成り立っています。

### 役割分担のメカニズム

```
[会議音声 / 動画] 
       ↓
【Step 1: Gemini (1.5 Pro)】
  - 圧倒的なコンテキスト窓（最大200万トークン）で、
    長時間の会議（数時間）を一発で精度の高いテキストに文字起こし。
       ↓（生データ・一次議事録）
【Step 2: Claude (3.5 Sonnet)】
  - 業界最高峰の「論理的思考力」と「自然な日本語表現」で、
    決定事項、重要発言、ネクストアクション（期限・担当者）を完璧に抽出。
       ↓
【成果物：完璧な議事録】
```

#### なぜGeminiだけ、Claudeだけではダメなのか？
* **Gemini単体の場合：**
  文字起こしの網羅性やGoogle Workspace（Meet等）との連携は神がかり的ですが、要約をさせると「箇条書きが長すぎる」「ビジネスライクなニュアンスの微調整が苦手」という弱点があります。
* **Claude単体の場合：**
  要約や思考力は最強ですが、長時間の音声ファイルを直接読み込ませるにはトークン制限（入力制限）やコスト面で不利になります。

## 2. Gemini と Claude の性能・価格比較

「プロ版（有料プラン）」を基準に、両者のスペックとコストを比較してみましょう。

## 3. サクラレビュー排除！ネット上のリアルな口コミ・評判

ステマやサクラレビューを徹底排除し、X（旧Twitter）や海外のReddit、エンジニアコミュニティから集めた**「本音のメリット・デメリット」**をまとめました。

### リアルな良い口コミ（本音）

> 💡 **「Geminiでドキュメントに書き出して、Claudeに『これSlack用に3行でまとめて』と投げるフローが最強。自分で書くより10倍速いし、抜け漏れがない。」** (IT企業マネージャー)

> 💡 **「Claude 3.5 Sonnetの要約は、本当に文脈を読んでくれる。『Aさんは乗り気ではないが、Bさんの説得で渋々承諾した』みたいなニュアンスまで正確に抽出してアクションプランに落とし込んでくれる。」** (フリーランスWebディレクター)

### リアルな悪い口コミ（ここがイマイチ）

> ⚠️ **「Claudeは長文を投げすぎると、すぐに『メッセージ上限に達しました』となって数時間使えなくなる。Geminiのように何も考えずに何万文字もブチ込むのには向いていない。」** (システム開発者)

> ⚠️ **「GeminiのMeet文字起こしは便利だけど、時々専門用語や固有名詞をめちゃくちゃに変換する。それをそのままClaudeに渡すと、Claudeが気を利かせすぎて誤情報を真実のようにまとめてしまう（ハルシネーション）。」** (マーケター)

**【対策】** GeminiからClaudeにデータを渡す際、専門用語の辞書登録や、プロンプトで「固有名詞の誤字と思われる部分は前後の文脈から修正するか、保留にしてください」と指示を入れるのがコツです。

## 4. すぐに使える！Claude用「議事録抽出」最強プロンプト

Geminiで出力した文字起こしテキストを、Claudeに流し込むだけで使えるプロンプト（指示文）を公開します。

```markdown
# 目的
以下の「Geminiで作成された会議の文字起こしテキスト」を分析し、ビジネスに直結する超高精度な議事録を作成してください。

# 出力フォーマット
## 1. 会議のサマリー（3行で）
- [要約1]
- [要約2]
- [要約3]

## 2. 決定事項（決定されたこと、合意事項のみ）
- [決定事項A]（決定の背景も1文で記載）
- [決定事項B]

## 3. 次回へのアクションアイテム（ToDo）
| タスク内容 | 担当者 | 期限 | 優先度 |
| :--- | :--- | :--- | :--- |
| 例：デザインの修正案提出 | 山田 | 10/25 | 高 |

## 4. 保留事項・次回議論すべき課題
- [保留事項1]

# ルール
- 専門用語や固有名詞に誤字脱字があると思われる場合は、文脈から推測して正しい言葉に補正してください。
- 誰が何を発言したか、意見の対立や議論のプロセスが重要である場合は、そのニュアンスを崩さずに記載してください。
```
