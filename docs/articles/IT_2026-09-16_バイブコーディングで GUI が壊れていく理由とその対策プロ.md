## 1. なぜバイブコーディングでGUIは壊れていくのか？3つの根本原因

AIに「それっぽい指示」を繰り返していると、最初は完璧だった画面が、徐々に崩壊（デグレード）していきます。原因は主に以下の3点です。

### 原因①：AIの「局所的最適化」と全体像の喪失
AIは、指示された「ボタンの追加」や「色の変更」といった**局所的な修正**を最優先します。その際、全体レイアウトを定義しているCSSや、親コンポーネントの影響度を無視して、無理やりスタイル（`position: absolute` や `!important` など）をインラインで書き込むため、徐々にレイアウトが破綻します。

### 原因②：コードのスパゲッティ化（技術負債の超高速蓄積）
バイブコーディングでは、人間がコードの構造をレビューしません。AIは「動けばいい」精神で、不要になった古いコード（デッドコード）を残したまま新しいコードを継ぎ足していきます。これが重なると、CSSの競合や状態管理（State）の不整合が発生し、画面がバグまみれになります。

### 原因③：コンテキストウィンドウ（文脈理解）の限界
チャットのやり取りが長くなると、AIは「初期に設定したデザインシステム」や「全体のレイアウト方針」を忘れてしまいます。その結果、急にテイストの違うボタンや、おかしな余白（Margin/Padding）を生成し始めるのです。

## 2. GUI崩壊を防ぐ！「黄金の対策プロンプト」テンプレート

バイブコーディングでGUIを崩壊させないためには、AIに**「全体の整合性を保ったまま、コンポーネント指向で修正させる」**制約をかける必要があります。
Cursorの `.cursorrules` や、ChatGPT/Claudeのシステムプロンプト、あるいは指示の冒頭に以下のテンプレートを貼り付けて使用してください。

### 【コピペ推奨】GUI崩壊防止プロンプト

```markdown
# 役割と目的
あなたは一流のフロントエンドエンジニアおよびUI/UXデザイナーです。
既存のコードベースに新しい機能を追加・修正する際、絶対に「レイアウトや既存のGUIを破壊しない」ことを最優先してください。

# 修正ルール（厳守事項）
1. **影響範囲の分析（Think Step-by-Step）**:
   コードを修正する前に、その修正が「親コンポーネント」「隣接する要素」「全体のレスポンシブデザイン」にどう影響するかを思考し、箇条書きで簡潔に述べてからコードを提示してください。
2. **デザインシステムの維持**:
   既存のCSS（Tailwind CSS / CSS Modules等）のカラーパレット、フォントサイズ、余白（Padding/Margin）のルールを厳格に踏襲してください。独自のインラインスタイル（特に `position: absolute` や、むやみな `z-index`、`!important`）を新規に追加することは禁止します。
3. **リファクタリングの併行**:
   不要になった古いコードや重複したスタイルは、放置せず必ずクリーンアップ（削除・統合）してください。
4. **差分（Diff）のみの提示**:
   ファイル全体を再生成するのではなく、どの部分をどのように変更するのか明確なDiff（差分）で提示してください。これにより、意図しないコードの先祖返りを防ぎます。

# 出力フォーマット
1. 【影響度分析】：（修正前に検討したこと）
2. 【修正内容】：（なぜそのコードにするのかの説明）
3. 【修正コード】：（差分形式、またはコンポーネント単位）
```

**💡 効果：** このプロンプトを挟むだけで、AIが「あ、既存のレイアウトを壊しちゃダメなんだな」と認識し、慎重にコードを書き直すようになります。コピペミスや先祖返りも劇的に減ります。
