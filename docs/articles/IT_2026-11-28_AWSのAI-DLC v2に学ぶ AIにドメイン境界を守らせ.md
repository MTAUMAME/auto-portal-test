## 💡 AI-DLC v2とは？なぜ「ドメイン境界」の保護が不可欠なのか？

従来型のAI導入では、「1つの巨大なAIモデルに全てのプロンプトとデータを投げ込む」手法が一般的でした。しかし、これには重大なリスクが存在します。

*   **人事データが一般社員向けチャットボットに漏洩する**
*   **顧客対応AIが社内の未公開開発ロードマップを勝手に回答する**
*   **AIエージェントが権限外のAPI（決済・削除など）を実行してしまう**

AWSの**AI-DLC v2**は、DDD（ドメイン駆動設計）の概念をAIアーキテクチャに移植した最新の設計フレームワークです。

```
[ ユーザー要求 ]
      │
      ▼
┌──────────────┐   (IAM / Guardrails)
│ Domain Router│ ──────────────┐
└──────┬───────┘               │ 境界を監視・制御
       │                       ▼
       ├───► [ 営業ドメイン AI Agent ] ──► (営業DBのみアクセス可)
       ├───► [ 開発ドメイン AI Agent ] ──► (GitHub/Jiraのみアクセス可)
       └───► [ 人事ドメイン AI Agent ] ──► (人事システムのみアクセス可)
```

### AI-DLC v2の3大コア原則

1. **コンテキストの完全分離（Context Isolation）**: ドメインごとに最適化された小規模なエージェント（またはプロンプト）を分散配置する。
2. **ポリシー主導型ガバナンス（Guardrails & IAM）**: AIの挙動をコードではなく、AWS Bedrock GuardrailsやIAMロールによってハードウェアレベルで制限する。
3. **明示的なハンドオフ（Explicit Handoff）**: ドメインを跨ぐ処理は、AI同士の口頭でのやり取りではなく、スキーマ化されたAPIを介してのみ許可する。
