## 1. なぜ今「アクセスキーの脱却」が必要なのか？

結論から言うと、**「永続的なアクセスキー（AKIA...から始まるやつ）を発行・ローカル保存する運用」自体がすでに時代遅れ（アンチパターン）**です。

AI時代の開発では、コードの自動生成や補完が強力な反面、意図せずクレデンシャル（認証情報）がコード内に紛れ込むリスクが高まっています。

### 漏えいした際のリスク
*   **不正マイニング（クリプトジャッキング）：** 超高スペックなEC2インスタンスを大量生成される
*   **機密データの窃取・ランサムウェア：** S3バケット内のデータ削除・暗号化
*   **巨大な請求額：** 一晩で数十万〜数千万円の損害

## 2. AWSアクセスキー漏えいリスクを劇的に減らす【4つの実践手順】

ここからは、今すぐ導入すべき具体的なセキュリティ手順をステップバイステップで解説します。

### STEP 1：原則「IAMユーザーのアクセスキー」を廃止する
まずは静的なアクセスキーを使わない仕組みを作ります。

*   **AWS IAM Identity Center（旧AWS SSO）の利用:**
    ローカル開発環境（CLI）からのアクセスは、永続キーではなく**一時的なトークン（CLI credentials）**を発行する仕組みに切り替えます。
*   **IAM Role（ロール）の活用:**
    EC2やAWS LambdaなどのAWSサービス間連携では、必ず「IAM Role」をアタッチし、コード内にキーを書かないようにします。

### STEP 2：どうしても必要な鍵は「AWS Secrets Manager」で自動回転
システム外部（オンプレサーバー等）からの接続などでどうしても静的キーが必要な場合は、**AWS Secrets Manager**を使用します。

*   アクセスキーを暗号化して安全に保管。
*   **「自動ローテーション機能」**を設定し、30日ごとにキーを自動更新する。

### STEP 3：コードコミット前の「ガードレール」を設置（Git-secrets / TruffleHog）
人間やAIが誤ってコードにキーを書き込んでも、GitHubにPushされる前にブロックする仕組みを入れます。

```bash
# git-secrets の導入例（Mac）
brew install git-secrets
git secrets --install
git secrets --register-aws
```
これだけで、AWSアクセスキーのパターンが含まれるコードのコミットをローカルで強制ストップできます。

### STEP 4：「Amazon GuardDuty」で万が一の漏えいを数分で検知
もしキーが漏えいしても、被害を最小限に抑えるために**Amazon GuardDuty**を有効化しておきます。
GuardDutyは機械学習を用いて、「普段と違うIPからのアクセス」や「異常な大量リソース作成」を検知し、即座に管理者へ通知・アクセス自動遮断（Lambda連携）を行ってくれます。

## 3. 主要AWSセキュリティサービスの【価格・性能比較】

対策に使われる主要3サービスのコストと特徴を比較しました。

| サービス名 | 主な用途 | 価格感（目安） | パフォーマンス・セキュリティ効果 |
| :--- | :--- | :--- | :--- |
| **AWS Secrets Manager** | 認証情報の安全な保管・自動ローテーション | **$0.40** / シークレット / 月<br>（APIリクエスト $0.05 / 10,000回） | **【高】** 自動回転が強力。コストはやや高いが安全度は抜群。 |
| **AWS SSM Parameter Store** | 設定値・認証情報の保管（SecureString） | **標準パラメータは無料**<br>（高度なパラメータは有料） | **【中〜高】** コストを抑えたいならこれ。自動ローテーション機能は自作が必要。 |
| **Amazon GuardDuty** | 脅威検知（漏えいキーの悪用検知） | 30日間無料体験あり<br>分析ログ量に応じた従量課金（月数百円〜） | **【最高】** 漏えい後の保険として必須。AIによる異常検知の精度が非常に高い。 |
