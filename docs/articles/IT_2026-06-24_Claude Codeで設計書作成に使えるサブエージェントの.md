## 1. Qiitaで話題！「Claude Codeサブエージェントシステム」とは？

元となったQiita記事では、Anthropic社がリリースした画期的なCLIツール**「Claude Code」**を使い、**要件定義・基本設計・詳細設計の各工程を専門に担当する「サブエージェント」を疑似的に作り出す方法**が紹介されています。

### なぜ「サブエージェント」が必要なのか？
1つのAIに「仕様書作って！」と丸投げしても、抽象的な回答しか返ってこないことが多々あります。
そこで、**プロセスごとに特化した役割（エージェント）を分割してClaudeに演じさせる**ことで、プロのエンジニア顔負けの成果物を作成できます。

### 設計書作成の3ステップワークフロー

```
[人間の指示/要望]
       │
       ▼
1. 【要件定義エージェント】 ──＞ 要件定義書 (Markdown)
       │
       ▼
2. 【基本設計エージェント】 ──＞ システム構成・API定義
       │
       ▼
3. 【詳細設計エージェント】 ──＞ クラス図・シーケンス図・タスク分割
```

1. **要件定義エージェント**: ユーザーの曖昧なアイデアから、システム化に必要な要件（機能・非機能）を洗い出す。
2. **基本設計エージェント**: 要件定義をもとに、フォルダ構成、使用技術、DB設計を策定する。
3. **詳細設計エージェント**: 各モジュールの処理フローやAPI仕様書（Markdown）を自動生成する。

Claude Codeの強力なファイル操作能力（`write_to_file`など）を組み合わせることで、**コマンドライン上で対話するだけで、気がつけばローカルフォルダに完璧な設計ドキュメント群が生成されている**という魔法のような体験が可能になります。

### 比較のポイント：なぜドキュメント作成は「Claude Code」が一歩リードなのか？
Claude Codeの心臓部である**「Claude 3.5 Sonnet」**は、日本語のニュアンス理解と構造化テキスト（MarkdownやMermaid図）の生成において、GPT-4oを圧倒しています。また、プロジェクト全体のコンテキスト（ソースコード全体）を理解した上で設計書を書かせる能力が極めて高いため、**「コードと設計書に乖離がない状態」**を保ちやすいのが最大のメリットです。
