## 1. 「Claude Codeの規律をHookに降ろす」とはどういうことか？

Claude Codeがなぜ優秀なのかというと、単に賢いだけでなく、プロジェクトのルートにある**`CLAUDE.md`**などのルールファイルを厳格に読み込み、**「ビルドコマンド」「テストコマンド」「コード規約」を自律的に実行して確認する「規律」**があるからです。

この「規律（ルール駆動プロセス）」を、Gitのコミット前（`pre-commit`）や、ローカルの自動実行スクリプト（Hook）に移植します。

### 具体的な仕組み
1. **`CLAUDE.md`の作成**: プロジェクトのビルド、テスト、リファクタリングのルールを明文化。
2. **Git Hook（Huskyやシェルスクリプト）の構築**: コミット時やコード保存時に、変更された差分と`CLAUDE.md`のルールをセットにして、Claude 3.5 HaikuのAPIに流す。
3. **自動テストの強制**: Haikuが生成したコードは、Hook側で自動的に`npm test`や`cargo test`などのローカルテストを実行。テストが通るまで、Haikuに自動でリトライ（最大3回など）させる。

```bash
# git hook (pre-commit) のイメージ
# 1. 差分を検出
# 2. CLAUDE.md（規律）と差分をHaiku APIに送信
# 3. 返ってきたコードをテスト
# 4. テストが通ればコミット承認、落ちればHaikuにフィードバックして修正
```

この「規律（ルール追従 ＋ テスト駆動のループ）」を強制することで、**Haikuの「指示を忘れがち」という弱点をシステム側で完全にカバー**。結果として、Sonnet並みの堅牢性をHaikuの爆速・低コストで実現できるのです。
