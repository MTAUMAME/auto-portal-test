| 項目 | Claude Code | Cursor (Codex/VS Code系) |

## 徹底比較：価格と性能

### 1. 料金システム（コストパフォーマンス）

ここが最大の分岐点です。

```
【Cursor】
月額 $20 (約3,000円) のサブスクで、高性能モデル（GPT-4o, Claude 3.5 Sonnet）が「実質使い放題（Fast枠制限あり、以降低速）」。

【Claude Code】
Anthropic Consoleの「従量課金（API利用料）」。
1トークンあたりの課金のため、大規模プロジェクトでコンテキストを読み込ませると、1日で数ドル〜数十ドルが吹き飛ぶ。
```

*   **結論：** ライト層〜通常開発は**Cursorの勝ち**。Claude Codeは「ここぞというバグ退治」に絞らないと、月額料金がCursorを軽く超えます。

### 2. 開発スピードと「settings.json」の壁

「Claude Codeはエージェントだから、指示するだけでファイル作成からテスト、Gitコミットまでやってくれて速い」と言われます。確かにそれは事実です。

しかし、**「自分の好みにカスタマイズされた開発環境（settings.jsonやショートカット）」がある開発者の場合、話が変わります。**

*   **Cursor（VS Code）の強み：**
    長年培ったVimキーバインド、自動保存時のLinter/Formatter（Prettier/ESLint）の挙動、スニペット。これらはすべて`settings.json`に紐づいています。Cursorなら、AIに「Cmd+K」で指示しつつ、手動での微調整が1秒で終わります。
*   **Claude Codeの弱み：**
    CLI上で「コードを書き換えた」と表示されても、ローカル環境のLinterルールと衝突してエラーが出る、インデントが崩れるなどの手戻りが発生しやすい。結局エディタ側で開き直して手動修正する羽目になり、二度手間に。

> **「settings.jsonを育てた側が速い」の真意**
> AIに100%丸投げするならClaude Codeですが、実務の「AI 7割：人間 3割」の高速コーディングにおいて、人間側の3割の効率を最大化するのは、高度にカスタマイズされたCursor環境です。
