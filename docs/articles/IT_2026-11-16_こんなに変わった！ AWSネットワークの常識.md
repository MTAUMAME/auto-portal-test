## 1. ここが変わった！AWSネットワークの「新・常識」トップ3

### 常識①：マイクロサービス/AI API接続は「VPC Lattice」でIPアドレス設計不要に
*   **昔：** VPC PeeringやTransit Gatewayを張り巡らせ、IPアドレスの重複（CIDR重複）に頭を抱えながらルーティングを設定していた。
*   **今（VPC Lattice）：** アプリケーション層（L7）で安全に接続。IPアドレスや複雑なネットワーク構造を意識せず、**「サービス名」で相互接続が可能**に。認証・認可も一括管理でき、AIモデルのAPI連携に最適。

### 常識②：AI学習のボトルネックを解消する「800Gbpsネットワーク＆EFA」
*   **昔：** クラウド上の分散学習はネットワーク帯域がネックになり、オンプレミスのInfiniBandに劣ると言われていた。
*   **今（EFA & UltraClusters）：** **Elastic Fabric Adapter (EFA)** により、OSをパススルーしてGPU間通信を高速化。最新のP5インスタンス等では最大800Gbpsの帯域を実現し、大規模言語モデル（LLM）の学習速度が飛躍的に向上。

### 常識③：高いNAT Gatewayを回避する「Express One Zone」とコスト最適化手法
*   **昔：** 外部API叩くためだけにNAT Gatewayを置き、転送量と時間給で毎月万単位の請求に泣いていた。
*   **今：** **S3 Express One Zone**などの超高速・低遅延な単一AZ構成の登場や、VPC Endpoint（Gateway/Interface）の最適化、Cloud WANを活用したグローバル転送コストの圧縮など、「賢く削る」選択肢が激増。

## 2. 徹底比較！新旧AWSネットワーク構成（性能・コスト）

主要な接続・通信パターンの「従来」と「最新」を比較しました。

| 項目 | 従来構成 (Transit Gateway等) | 最新構成 (VPC Lattice / Cloud WAN) | 性能・運用の違い | コストインパクト |
| :--- | :--- | :--- | :--- | :--- |
| **VPC間・サービス間接続** | Transit Gateway / VPC Peering | **VPC Lattice** | IP設計不要。L7でのルーティングとIAM統合制御 | ルーター維持費を削減、通信量に応じた従量課金で小規模〜中規模は大幅カット |
| **グローバル拠点接続** | 複雑なVPN + TGWのメッシュ構成 | **AWS Cloud WAN** | ポリシーベースでグローバルネットワークを一元管理 | 運用人件費（オペアンプ）を大幅削減 |
| **超高速分散処理 (AI/HPC)** | 通常のSR-IOV (25〜100Gbps) | **EFA (Elastic Fabric Adapter)** | レイテンシを極限まで削減、GPU利用率を最大化 | インスタンス稼働時間を短縮できるため結果的にクラウド総コスト削減 |
