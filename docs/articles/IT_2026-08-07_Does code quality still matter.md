## 1. なぜAI時代に「コード品質」がより重要になるのか？

「AIが動くコードを出力してくれるからOK」という考え方は、短期的な個人開発なら通用しますが、中長期的なプロジェクトでは**「技術的負債の爆発」**を招きます。

### ① 「ゴミ（低品質なコード）」を入力すると、AIは「洗練されたゴミ」を出力する
AI（特にGitHub CopilotやCursor）は、**既存のコードベース（コンテキスト）を学習・参照して次のコードを提案**します。
あなたのプロジェクトのコード品質が低いと、AIはその「悪い癖」を真似して、さらにスパゲッティコードを量産します。

### ② デバッグを行うのは、結局「人間」である
AIが生成したコードにバグがあった場合、コード品質（可読性、モジュール化）が低いと、人間がデバッグするのに何倍もの時間がかかります。「生成は1秒、デバッグに3日」という本末転倒な事態を防ぐ必要があります。

### ③ セキュリティとスケーラビリティの担保
AIは「動くコード」を作るのは得意ですが、「セキュリティ要件を満たし、負荷に耐えられるアーキテクチャ」を設計するのはまだ苦手です。
