# SREとは？AI時代に重要性が急上昇している理由

 SRE（Site Reliability Engineering）とは、Googleが提唱した**「ソフトウェアエンジニアリングの力を使って、システムの信頼性を向上させるアプローチ」**です。

従来の「運用保守（システムが壊れたら直す）」とは異なり、**自動化、コード化（IaC）、そして最新のAI技術（AIOps）**を駆使して、システムが落ちない仕組みを未然に築くことを目的としています。

### DevOpsとの違いは？
*   **DevOps:** 「開発（Dev）と運用（Ops）が協力して迅速に価値を届ける」という**哲学・マインドセット**。
*   **SRE:** DevOpsの哲学を具体化するための**実装方法・具体的な職種**（「class SRE implements DevOps」とも言われます）。

最近では、**ChatGPTなどのLLMを活用してアラート検知やトラブルシューティングを自動化する「AI×SRE」**の領域が急速に発展しており、エンジニア市場価値が最も高い職種の一つとなっています。

# AWSで始めるSRE：必須サービスと3つのステップ

AWS（Amazon Web Services）は、SREを実践するための強力なサービス群群を提供しています。まずは以下の3ステップから始めましょう。

### STEP 1：システムの「可観測性（Observability）」を確保する
システムがどう動いているか見えなければ、信頼性は担保できません。
*   **Amazon CloudWatch:** メトリクス収集、ログ管理、アラート通知の基本。
*   **AWS X-Ray:** 分散トレーシング。リクエストがどのマイクロサービスで遅延しているかを可視化。

### STEP 2：運用の自動化（Toilの削減）
SREでは、手作業で行う定型業務（Toil：トイル）を嫌います。
*   **AWS Systems Manager (SSM):** パッチ適用や設定変更を自動化。
*   **AWS Lambda:** アラートをトリガーに、自動復旧スクリプトを実行。

### STEP 3：障害に強いインフラ構成（レジリエンス）
*   **AWS Resilience Hub:** アプリケーションの回復力を定義、測定、改善する最新ツール。
*   **AWS Chaos Simulator (FIS):** 意図的に障害を起こし、システムの耐性をテスト。

# 【比較】AWS vs Datadog vs New Relic

SREを始める際、最初の分岐点となるのが**「AWS純正ツールでいくか、外部SaaS（Datadog / New Relic）を導入するか」**です。価格、性能、そして今注目の「AI機能」で比較しました。

| 比較項目 | AWS (CloudWatch/X-Ray) | Datadog | New Relic |
| :--- | :--- | :--- | :--- |
| **特徴** | AWS純正の安心感とコスパ | 業界デファクト。美しく超多機能 | 課金体系がシンプル。APMに強み |
| **価格帯** | 従量課金（安価に始められる） | ホスト数課金（規模拡大で高額化） | ユーザー数＋データ量（予測しやすい） |
| **初期設定** | 簡単（ポチるだけで連携） | エージェント導入が必要 | エージェント導入が必要 |
| **AI・分析機能** | 異常検知（基本機能） | **Watchdog**（AIによる自動障害検知） | **New Relic AI**（自然言語でのデータ分析） |
| **おすすめ対象** | AWSだけで完結、予算を抑えたい | マルチクラウド、予算に余裕あり | コストを予測しつつ高度な監視をしたい |
