## 1. NTTPCが提唱する「コンテキスト設計力」とは？

NTTPCの解説記事によると、AIエージェント時代における「プロンプト」と「コンテキスト設計」の違いは以下のように定義されています。

| 項目 | プロンプトエンジニアリング（旧時代） | コンテキスト設計（これからの時代） |
| :--- | :--- | :--- |
| **主役** | 人間（都度指示を出す） | AIエージェント（自律的に判断・行動） |
| **アプローチ** | 1対1の「命令と応答」 | 複数AIが連携する「環境と仕組みの構築」 |
| **必要な要素** | 言語センス、質問の具体性 | データベース（RAG）、API連携、メモリ管理、ワークフロー設計 |
| **目的** | 単発のテキスト・画像生成 | 業務プロセスの完全自動化 |

### なぜ「コンテキスト設計」が重要なのか？
これからのAIは、「指示を待つツール」ではなく、**「目標を与えれば勝手にタスクを分解して実行するエージェント」**になります。
このAIエージェントが正確に動くためには、**「社内データ（RAG）」「過去の対話履歴（メモリ）」「外部ツールとの連携（API）」といった「文脈（コンテキスト）」を正しく整理し、AIに与えるインフラ**が必要です。

そして、この複雑なコンテキストを高速かつ安全に処理するために欠かせないのが、**高性能なGPUインフラ**なのです。
