## 1. なぜ安くなる？「プロンプト画像化」の仕組み

Claude 3.5 Sonnetをはじめとする最新のLLM（大規模言語モデル）は、高度な画像認識（Vision）機能を備えています。今回の手法は、この**「マルチモーダル機能」と「トークン課金の仕組み」**を逆手に取ったものです。

### テキスト vs 画像のトークン消費のカラクリ

通常、APIの料金は「トークン数（文字数のようなもの）」で計算されます。

*   **テキストの場合：** 
    複雑なシステムプロンプト、キャラクター設定、長大なコンテキストルールをテキストで記述すると、数万トークンに膨れ上がることがあります。APIを叩くたびに、この大量のトークン代が毎回フルで課金されます。
*   **画像の場合：**
    Claude（Anthropic社）の仕様では、入力された画像は解像度に応じた固定トークン数（最大でも1枚あたり約1,600トークン以下）に変換されて処理されます。

つまり、**「テキストで送ると20,000トークン消費する複雑な指示書」を、1枚の高解像度画像（PNG等）にまとめてVision APIに読み込ませることで、わずか1,600トークン分の料金に抑え込むことができる**のです。

## 2. 【比較】テキスト vs 画像入力のコスト＆性能

実際にこの手法（システムプロンプト画像化）を使った場合と、従来のテキスト入力の場合を比較してみました。

| 比較項目 | 従来のテキスト入力 | システムプロンプト画像化ツール |
| :--- | :--- | :--- |
| **消費トークン数（目安）** | 約 10,000 〜 30,000 トークン | **約 1,600 トークン（固定）** |
| **API費用（1回あたり）** | 約 $0.03 〜 $0.09 | **約 $0.0048 （約 1/10 以下）** |
| **指示の再現性（性能）** | 完璧（ロジックのブレが少ない） | 良好（ただし解像度やフォントに依存） |
| **レスポンス速度（速度）** | 高速（テキスト処理のみ） | やや低速（画像のデコード処理が発生） |
| **開発のしやすさ** | 容易（コードに直書き） | 変換の手間、ツール連携が必要 |

### 結論：どんな時に使うべき？
*   **推奨：** チャットボットのキャラクター設定、厳格な出力フォーマットのルール、FAQデータベースなど、**「毎回送信するが、内容は頻繁に変わらない長大なシステムプロンプト」**がある場合。
*   **非推奨：** リアルタイム性が最重視されるスピード勝負のアプリケーション。
