# DevContainerはもう古い？LLMエージェント開発を爆速にする「新・最強開発環境」とおすすめガジェット

こんにちは！ガジェット＆最新AI専門ブログの管理人です。

Dockerを利用して一瞬で開発環境を構築できる「VS Code DevContainer」。非常に便利で、筆者も長年愛用してきました。

しかし、**LLMエージェント（CrewAI, AutoGen, LangChainなど）をゴリゴリ開発するようになった今、私はDevContainerを完全に使わなくなりました。**

なぜ、あれほど便利だったDevContainerを捨てたのか？
そして、現在行き着いた**「LLMエージェント開発に最適化された最新環境」**とは何なのか？

今回は、その理由と代替となる最強システム、そして実際に使ってわかったリアルな口コミやコストパフォーマンス比較、おすすめのガジェットまで徹底解説します！

---

## 1. なぜLLMエージェント開発でDevContainerをやめたのか？

理由はシンプルに**「重さ（オーバーヘッド）」**と**「AIとの相性の悪さ」**です。

1. **ローカルLLM（Ollama等）やGPUとの連携が面倒**
   DevContainer内からホストマシンのGPUやローカルで動くLLM（Ollama）にアクセスする際、ポート転送やネットワーク設定が二度手間になります。
2. **起動の遅さが「AIの試行錯誤」のテンポを削ぐ**
   LLMエージェント開発は「プロンプト調整→実行」を何十回も高速で繰り返します。コンテナのビルドや再起動のわずかな待ち時間が、開発のクリエイティビティを著しく低下させます。
3. **Cursorなどの「AIネイティブエディタ」のパワーを100%活かせない**
   今や開発に欠かせないAIエディタ「Cursor」ですが、DevContainer（リモートコンテナ）経由だとインデックス作成やローカルファイル参照で微妙なラグやバグが発生することがあります。

---

## 2. 結論：移行した「現在のLLMエージェント開発環境」

現在、筆者が行き着いたのは**「AIネイティブエディタ × ローカル仮想環境（Venv/uv） × 圧倒的マシンパワー」**という超シンプルかつ高速な構成です。

* **エディタ:** **Cursor（Proプラン）**
  * VS Codeのフォークであり、AI機能（Composer）が最初から統合されている最強エディタ。
* **パッケージ管理:** **uv (by Astral)**
  * Rust製でPipの10〜100倍速い。コンテナを作らなくても、一瞬で綺麗な仮想環境が作れます。
* **ハードウェア:** **Apple Silicon Mac（M3 Max / 64GB以上）**
  * ローカルで「Llama-3」や「Command R+」などの量子化モデルを高速に動かすための「巨大な統一メモリ（Unified Memory）」が必須。
