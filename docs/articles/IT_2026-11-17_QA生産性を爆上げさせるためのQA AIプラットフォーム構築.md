# 🗣️ サクラレビュー排除！現場エンジニアのリアルな口コミ・評判

X（旧Twitter）、Reddit、Qiita、Quora等のエンジニアコミュニティから、**広告・プロモーション目的の投稿を徹底的に排除**した「本音の口コミ」を抽出しました。

### ⭕ 良い口コミ（リアルなメリット）

> **「MagicPodの自己修復はマジで助かる」**
> デザイン変更のたびにテストが落ちて修正する作業がほぼゼロになった。非エンジニアのQAメンバーもテストケースをガシガシ追加できるので、開発チームの負荷が激減した。（30代 Web系SRE）

> **「Claude 3.5 Sonnet × Playwright の自社QAbotがヤバい」**
> PR（プルリクエスト）を投げると、Claudeが変更点を分析してテストコードを自動生成、Playwrightでヘッドレス実行して結果をGitHubにコメントしてくれるパイプラインを作った。月額API代はわずか$30程度。コスパ最強。（20代 フロントエンドエンジニア）

### ❌ 悪い口コミ（現場が直面するギャップ）

> **「SaaS系はスケールすると価格が跳ね上がる」**
> AutifyやTestimは確かに便利だが、実行回数（クレジット）が増えると急激に高額になる。大規模プロダクトで毎コミットごとに全件テストを回すと破産する。（30代 開発ディレクター）

> **「完全自動化の夢を見ると火傷する」**
> AIの自己修復も万能ではない。意図的なUI変更なのか、バグによる表示崩れなのかをAIが誤認して「緑（成功）」判定にしてしまうケースがあった。最終的な確認ステップは人間が必要。（40代 QAエンジニア）

# 🛠️ 生産性を爆上げする「自社QA AIプラットフォーム」の推奨構成

「SaaSのコストが気になる」「自社特有の複雑なドメイン知識をテストに反映させたい」というチームにおすすめなのが、**LLMを活用した自社QAプラットフォームの構築**です。

### 構成イメージ（モダンQAパイプライン）

1.  **インプット**: GitHubのPR / Figmaのデザインデータ / Notionの仕様書
2.  **思考エンジン（LLM）**: **Claude 3.5 Sonnet**（視覚理解とコード生成能力が最強）
3.  **実行エンジン**: **Playwright** または **Cypress**
4.  **結果解析・通知**: Vision AIによる画面差分チェック ➔ Slack通知 / GitHubコメント

```text
[仕様書/PR/Figma] 
       │
       ▼
[Claude 3.5 Sonnet] ──(テストシナリオ・Playwrightコード自動生成)──► [GitHub Actions]
                                                                        │
[Slack通知 / AIバグ報告] ◄──(視覚差分＆ログ解析)── [Playwright実行 (Headless)]
```
