# 【衝撃】「Windows Server 2028」でレガシー技術が大量廃止！WSUS・SMB1.0・VBScript削除＆BIOS起動不可へ。今から始める移行・対策ロードマップ

こんにちは！最新ガジェット＆AI・ITインフラトレンドを追う当ブログへようこそ。

マイクロソフトから、次世代サーバーOSとなる**「Windows Server 2028」**に関するショッキングな（しかし時代の流れとしては当然の）ロードマップが話題となっています。

なんと、長年オンプレミス環境を支えてきた**「WSUS」や「SMB 1.0」、「VBScript」が完全に削除**されるほか、**「Windows PowerShell 5.1」や「WDS」が非推奨**に。さらに**レガシーBIOS（MBR）での起動すら不可能（UEFI必須）**になります。

「まだ先の話でしょ？」と思っているIT管理者やエンジニアの皆さん、**移行の準備は今すぐ始めないと間に合いません。**

今回は、この変更点の要点整理、クラウドvsオンプレのコスト・性能比較、ガチインフラエンジニアのリアルな口コミ（サクラ排除）、そして今買うべき対策ソリューション＆おすすめ教材を徹底解説します！

## 1. 何が変わる？Windows Server 2028の主な廃止・非推奨機能まとめ

マイクロソフトは「セキュリティ強化」と「クラウド（Azure）とのハイブリッド化」を猛烈に推し進めています。今回対象となったレガシー機能は以下の通りです。

| 機能 / 技術 | ステータス | 影響と対策 |
| :--- | :--- | :--- |
| **SMB 1.0** | **完全削除** | ランサムウェアの標的になりやすい旧規格。SMB 2.0/3.0への完全移行が必須。 |
| **VBScript** | **完全削除** | 昔作った資産（.vbs）が全滅します。PowerShell 7.xへの書き換えが必要。 |
| **WSUS** | **非推奨〜削除** | 従来のローカルアップデート管理が終了。Azure AutopatchやAzure Arcへ移行。 |
| **WDS (Deployment Services)** | **非推奨** | PXEブートによるOS大量展開の仕組み。MDTやAutopilot等の代替が必要。 |
| **PowerShell 5.1** | **非推奨** | WindowsデフォルトのPSは終了へ。オープンソースの**PowerShell 7.x**へ集約。 |
| **レガシーBIOS起動** | **サポート終了** | 完全UEFI化。古い古い物理サーバーや第1世代VMは起動すらできなくなります。 |

## 2. 移行先はどうする？「オンプレ更新」vs「Azureハイブリッド」性能・価格比較

レガシー切り捨てに対応するためには、**「物理サーバーの買い替え（UEFI/TPM 2.0対応）」**か**「Azureなどクラウドへの全面移行（またはハイブリッド）」**を選択する必要があります。

それぞれのコストと性能、運用負荷を比較しました。

### コスト・性能比較表

| 比較項目 | ① 最新オンプレサーバー更新<br>（Windows Server 2025/2028） | ② Azure ハイブリッド移行<br>（Azure Arc + オンプレ） | ③ フルクラウド移行<br>（Azure IaaS / PaaS） |
| :--- | :--- | :--- | :--- |
| **初期費用 (CAPEX)** | **高**（サーバー本体・ライセンス購入） | **中**（既存資産活用＋Arc導入） | **極小**（初期投資ほぼゼロ） |
| **運用費用 (OPEX)** | **低**（電気代・保守費のみ） | **中**（月額従量課金） | **高**（リソース依存の月額課金） |
| **パフォーマンス** | **最高**（ローカルNVMe等の超高速処理） | **高**（主要データはローカル配置） | **中〜高**（ネットワーク帯域に依存） |
| **WSUS/VBS代替え** | PowerShell 7書き換え＆手動設定 | **最優秀**（Azure Arcで一括自動管理） | **優秀**（Intune / Autopatch活用） |
| **BIOS不可への対応** | 最新ハードウェア購入で即解決 | 既存ハード＋仮想化で対応 | 考慮不要（全自動UEFI） |

### 結論：どれを選ぶべき？
*   **コスト重視＆自社運用**: ①の「最新物理サーバー＋PowerShell7化」
*   **運用効率＆最新セキュリティ**: ②の「Azure Arc導入によるハイブリッド運用」が最も現実的な落としどころです。
