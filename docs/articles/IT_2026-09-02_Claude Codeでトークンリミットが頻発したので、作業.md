## 1. エムスリーテックブログに学ぶ「Claude Codeトークン制限対策」

エムスリーのテックブログ「Claude Codeでトークンリミットが頻発したので、作業ごとにリミットを設定した」では、Claude Codeを実務に導入した際に直面した課題と、その具体的なハックが紹介されています。

### 課題：Claude Codeが「自律的すぎて」トークンをドブに捨てる
Claude Codeは非常に優秀で、指示を出すと自動でファイルを探索し、コードを書き換え、テストを実行します。
しかし、**「エラーが出る ➡ 自動で修正する ➡ また別のエラーが出る ➡ 自動で修正する…」**という**無限ループ（自律走行の暴走）**に陥ることがあります。

これにより、1回の指示で膨大なトークン（コンテキスト）が消費され、APIの利用制限（レートリミット）に達したり、高額な請求が発生したりしていました。

### 解決策：作業（ステップ）ごとに制約を設ける
エムスリーのエンジニアが導入したのは、**「Claudeに一度にやらせる作業の範囲を狭め、ステップごとに確認を入れる」**というアプローチです。

1. **`--max-steps` オプションの活用**
   Claude Code実行時に、AIが自律的に実行できるステップ数（ツール実行回数）に上限を設けます。
   ```bash
   # 例：最大5ステップまでしか自動実行させない
   claude --max-steps 5
   ```
2. **タスクの細分化（マイクロタスク化）**
   「〇〇の機能を実装してテストして」と丸投げするのではなく、「〇〇のファイルを作成して」「次にテストコードを書いて」と、1回のコマンドで消費するトークン量を意図的にコントロールします。
3. **対話型プロンプトでの「予算管理」**
   プロンプトの冒頭で「今回は〇〇の修正だけを行ってください。それ以外のファイルは読み込まないでください」と明確に制約（Scope）を提示します。

これらにより、開発効率を維持したまま、APIコストの爆発とトークンリミットの頻発を防ぐことに成功しています。
