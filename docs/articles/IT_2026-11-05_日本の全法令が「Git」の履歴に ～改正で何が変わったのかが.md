## 1. 3分でわかる！「全法令のGit化」何がすごくて何が問題？

### 〇 ここがすごい！
1. **改正の「差分（diff）」が一目瞭然**
   これまで「〇〇条の〇〇を××に改める」という難解な新旧対照表を読まなければならなかった法律の改正が、Gitの `diff`（差分表示）を使うことで「どこが追加され、どこが削除されたか」が赤と緑で一瞬でわかるようになります。
2. **タイムトラベル（履歴の遡及）が可能**
   「2020年時点の道路交通法はどうだったか？」が、コミット履歴を遡るだけで再現可能に。
3. **エンジニア・AI開発者が二次利用しやすい**
   GitHub等で公開されたことで、プログラミングやAIへの読み込みが圧倒的に容易になりました。

### ✕ ここが意外な「弱点」？（元記事の指摘）
Gitは元々**「プログラミング言語（テキストコード）」のために開発されたツール**です。そのため、自然言語である「法律（特にXML形式）」をそのまま流し込むと、以下の弱点が発生します。

* **行単位の差分問題**：Gitは「行」単位で差分を検出します。1行がめちゃくちゃ長い文章だと、たった1文字変わっただけで「行全体が変わった」と判定され、どこが変わったかわかりづらい。
* **データ構造（XML）との相性**：法令データはXML形式で管理されているため、タグの改行位置やインデントの違いだけで「大量の差分」として検出されてしまうノイズが発生する。
