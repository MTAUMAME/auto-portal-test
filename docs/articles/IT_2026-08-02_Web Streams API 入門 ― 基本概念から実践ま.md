## 1. Web Streams APIとは？ 基本概念をサクッと理解

従来のデータ処理では、例えば「1GBのファイル」を読み込む際、一度すべてのデータをメモリ（RAM）に展開してから処理を行う必要がありました。これでは、スマホや低スペックのPCではブラウザがクラッシュしてしまいます。

**Web Streams API**は、データを「チャンク（小さな塊）」に分割し、**流れる水（ストリーム）のように順次処理する仕組み**を提供します。

```
[データソース] ──(チャンク)──> [ReadableStream] ──> [TransformStream] ──> [WritableStream] ──> [表示/保存]
```

### 3つのコア概念
1. **ReadableStream（読み込みストリーム）**: データの受け取り口。Fetch APIの `response.body` などがこれに当たります。
2. **WritableStream（書き込みストリーム）**: データの出力先。ファイルへの書き込みや、画面への描画など。
3. **TransformStream（変換ストリーム）**: 途中でデータを加工・変換（例：圧縮、暗号化、テキストデコード）するフィルター。

### なぜ今、Web Streams APIなのか？
* **AI（LLM）との親和性**: OpenAIなどのAPIから返されるストリーミング応答を、フロントエンドでリアルタイムにレンダリングするのに最適。
* **エッジコンピューティングの台頭**: Cloudflare WorkersやVercel Edge Functionsなど、メモリ制限が厳しい環境で威力を発揮。

## 2. 【実践】Web Streams APIを使ってみよう！

最も実用的な**「Fetchしたテキストデータをリアルタイムにデコードしてコンソールに出力する」**コード例です。

```javascript
async function fetchAndStream(url) {
  const response = await fetch(url);
  
  // 1. ReadableStreamを取得
  const reader = response.body.getReader();
  // 2. テキストデコーダー（TransformStreamの代わりとして機能）を用意
  const decoder = new TextDecoder("utf-8");

  while (true) {
    // 3. データをチャンクごとに読み込む
    const { done, value } = await reader.read();
    
    if (done) {
      console.log("=== ストリーム終了 ===");
      break;
    }
    
    // 4. チャンク（Uint8Array）をテキストに変換して表示
    const chunkText = decoder.decode(value, { stream: true });
    console.log("受信データ:", chunkText);
  }
}
```

この処理を行うことで、数GBあるログファイルであっても、ブラウザのメモリを一切圧迫せずに先頭から順に処理することが可能になります。
