ついにGitHubがこの問題に対してメスを入れました。GitHubは、**ユーザーあたりのプルリクエスト数に上限を設定できる新機能**を導入することを発表しました。

## 1. ニュース概要：GitHubが「AIによるPRスパム」に歯止め

Microsoft傘下のGitHubは、リポジトリのメンテナー（管理者）が、**特定のユーザーが一定期間内に作成できるプルリクエスト（PR）の数を制限できる機能**を導入しました。

### なぜこの機能が必要なのか？（背景）
ChatGPTやGitHub Copilot、Cursorなどの普及により、誰でも簡単にコードを出力できるようになりました。しかし、その弊害として、以下のような問題が深刻化しています。

* **「とりあえずAIに作らせた」動かないコードのPR乱発**
* **OSS（オープンソース）プロジェクトへの、実績作り目的の低品質PRスパム**
* **メンテナー（レビュー担当者）の深刻なリソース不足と疲弊**

今回の新機能により、管理者は「1ユーザーあたり1日5件まで」といった制限をかけることが可能になり、手当たり次第に送られてくるAI製PRを物理的にシャットアウトできるようになります。

AIによるPRが制限されるということは、**「より高精度で、一発で通る質の高いコード」をAIに書かせる技術**が求められる時代になったことを意味します。

現在人気のAIコーディングツール3社を、価格と性能で比較しました。

* **開発効率最大化なら「Cursor」**：月額20ドルですが、プロジェクト全体をAIに読み込ませる（@Codebase機能）精度が群を抜いており、現在エンジニアの間で最も熱い支持を得ています。

## 3. サクラ排除！開発者のリアルな口コミ・評判

SNSや開発者コミュニティ（X、Reddit、はてなブックマークなど）から、広告・サクラレビューを排除した「本音の口コミ」を厳選してまとめました。

### 🟢 賛成・ポジティブな意見
> 「OSSのメンテナーだけど、まじで神機能。Copilotが適当に吐き出した、動きもしないコードのPRを1つずつ閉じる作業に魂を削られていたから助かる。」（30代・Webエンジニア）

> 「AIが悪いんじゃない、AIのコードをノーチェックで投げる人間が悪い。この制限によって、出す前に『本当にこれで動くか？』とテストする癖がつくはず。」（20代・フロントエンド）

### 🔴 懸念・ネガティブな意見
> 「スパム対策としては良いけど、初心者のコントリビュート（貢献）のハードルが上がるのが心配。ハッカソンとかで一気にPR送りたい時に引っかからないか？」（20代・学生）

> 「根本的な解決にはなってない。PRの数制限じゃなくて、AIが生成したPRを自動で検知して弾くCI/CDツールの方が欲しい。」（40代・インフラエンジニア）
