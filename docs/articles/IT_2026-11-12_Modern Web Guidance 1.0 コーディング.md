# 【衝撃】AIは「古くさいコード」を書いている？Googleが明かす「Modern Web Guidance 1.0」の正体と最新AIエージェント比較

「CursorやCopilotにコードを書かせたら一瞬で動いた！」と喜んでいませんか？
実はそのコード、**10年前の古い記述や、パフォーマンスの悪い非推奨なテクニック**が使われているかもしれません。

Google Chrome開発チームが発表した「Modern Web Guidance 1.0」は、**「AIエージェントには最新のWeb標準（ウェブプラットフォーム）の知識が圧倒的に不足している」**という問題を指摘し、それを解決するためのガイドラインです。

この記事では、開発者が知っておくべきAIコーディングの裏側と、今選ぶべき最強のツール、ワークスペース環境まで徹底解説します！

## 1. 3分でわかる「Modern Web Guidance 1.0」の要点

Googleが指摘する、現在のAIコーディングエージェント（Claude 3.5 Sonnet, GPT-4oなど）が抱える課題と解決策は以下の通りです。

### ⚠️ AIコーディングエージェントの課題
1. **学習データの風化（Old Best Practices）**
   AIは過去の大量のWebサイトや古いQiita/Stack Overflowを学習しているため、**すでに廃止されたJavaScriptライブラリや、現代ではCSSだけで実装できるアニメーションをJSで書こうとする**癖があります。
2. **Web Baseline（最新のWeb標準）の未反映**
   現在のWebブラウザは「Popover API」や「CSS `:has()`」、「Container Queries」など超強力な標準機能を備えています。しかしAIはこれらを知らないか、互換性を恐れて古いPolyfill（互換コード）や肥大化したJSライブラリを提案しがちです。
3. **アクセシビリティ・パフォーマンスの低下**
   `<div>`のネスト祭り（Div Soup）や、LCP（表示速度）を悪化させるコードを無意識に生成してしまいます。

### 💡 Googleの解決策：「Modern Web Guidance 1.0」
Googleは、AIが**「現代のWeb標準に準拠したベストなコード」**を生成できるように、AIプロンプトやRAG（検索拡張生成）に組み込めるナレッジベース「Modern Web Guidance 1.0」をオープンソースで提供し始めました。

## 4. 今すぐ実践！AIに「現代的なコード」を書かせる裏ワザ

Googleの「Modern Web Guidance 1.0」の思想を今すぐ自分の環境に取り入れるには、**AIエージェントのシステムプロンプト（Cursorの`.cursorrules`など）に以下の制約を追加する**のが最も効果的です。

```text
【AIへの指示文例】
- 最新のWeb標準（Web Baseline 2024以降）に準拠したコードを出力してください。
- 不要なJavaScriptライブラリの使用を避け、できる限りHTML5のセマンティック要素やCSS（:has, Container Queries, Popover API等）で実装してください。
- パフォーマンス（Core Web Vitals）とアクセシビリティ（WCAG 2.1）を意識したコードにしてください。
```
