## 1. 207,039点を叩き出した「3人のClaude Code × Slack」システムとは？

今回話題となったチームの戦術は非常にシンプルかつ合理的です。
人間3人のチームそれぞれが**専門特化させたClaude Code**をCLI上で稼働させ、それらをSlackのチャンネル経由で同期・並行処理させました。

```
 [人間A: DB担当] ──> [Claude Code: DB最適化] ──┐
                                             ├──> [Slack 共通チャンネル] ──> 本番反映＆ベンチ実行
 [人間B: App担当] ──> [Claude Code: コード改修] ──┤                              (スコア: 207,039)
                                             │
 [人間C: インフラ担当] ──> [Claude Code: Nginx/Redis] ┘
```

### なぜこの構成が最強だったのか？
1. **コンテキストの分離と集中**: 1つのAIにすべてを任せず、DB（N+1解消・インデックス張替え）、App（Go/Rustの高速化）、インフラ（Nginx/Kernelパラメータ調整）に役割を分割。
2. **Slackを「共有メモリ」として利用**: Claude Codeが変更したコードやベンチマーク結果、ボトルネック分析をSlackボット経由で自動投稿。互いの干渉を防止。
3. **人間は「承認ボタン」を押すだけ**: CLI側での実行許可（`y/n`）と最終的なデプロイ判断のみを人間が担当。

結果として、通常なら人間が数時間かかるチューニングを**わずか数分単位**で回し続け、20万点超えという前人未到のスコアを達成しました。

## 3. サクラなし！エンジニアの「ガチ」な口コミ・評判（良い点・悪い点）

* **「API代が溶ける」**: 複雑なリファクタリングを連続でさせると、1日で数千円〜1万円以上のトークンを消費することがある。（※API従量課金の場合）
