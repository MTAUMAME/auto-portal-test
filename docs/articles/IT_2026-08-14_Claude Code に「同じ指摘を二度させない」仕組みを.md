## 1. Claude Codeに「同じ指摘を二度とさせない」hook仕組みとは？

### なぜAIは同じミスを繰り返すのか？
通常、AIチャットやCLIツールは、セッション（会話）が変わると過去のコンテキスト（文脈）を忘れてしまいます。そのため、新しいターミナルでClaude Codeを立ち上げるたびに、「セミコロンは省略して」「テストコードはVitestで書いて」といった指示を出し直す必要がありました。これが地味にトークン（従量課金）と時間の無駄になります。

### 解決策：git hookとカスタムルールを連携させた自動学習システム
Claude Codeは、プロジェクトのルートディレクトリにある環境設定や、シェルスクリプトと連携（hook）させることができます。

今回は、**「Claudeが修正した内容や、人間が指摘したメモを自動で『ルールブック』に蓄積し、起動時に必ず読み込ませる仕組み」**を作ります。

#### 【実装手順】

1. **プロジェクトルートにルールファイルを作成**
   `MEMORIES.md`（または `.clauderules`）というファイルを作成します。ここには「守るべきローカルルール」や「過去の失敗」が蓄積されます。

2. **`.clauderc`（または起動スクリプト）にhookを仕込む**
   Claude Codeの起動時（pre-command）に、自動的に`MEMORIES.md`の内容をシステムプロンプトに注入する、もしくはGitのコミット時に「今回Claudeが修正した内容の要約」を`MEMORIES.md`に自動追記するhook（シェルスクリプト）を作成します。

```bash
#!/bin/bash
# .git/hooks/pre-commit または Claude起動スクリプトに仕込む例
# 直前のコミットや修正ログから「教訓」を抽出し、ルールに自動追記する

echo "---" >> MEMORIES.md
echo "【自動更新された開発ルール】" >> MEMORIES.md
git diff HEAD~1 | claude "この差分から、今後の開発で守るべきコーディング規約や注意点を1行で要約して" --once >> MEMORIES.md
```

3. **効果**
   これにより、Claude Codeを起動するたびに、過去の「あ、そこ直して」というやり取りが自動でコンテキストに注入されます。**「学習し続けるAIパートナー」**がローカル環境に誕生するわけです。

## 2. 徹底比較！Claude Code vs 主要AIコーディングツール

AI開発ツールを選ぶ上で最も重要な「価格」「性能」「カスタマイズ性」を比較しました。

| 機能・項目 | **Claude Code** (Anthropic) | **Cursor** (独自フォークIDE) | **GitHub Copilot** |
| :--- | :--- | :--- | :--- |
| **主なUI** | ターミナル (CUI) | 専用エディタ (GUI) | VS Code等の拡張機能 |
| **ベースモデル** | Claude 3.7 Sonnet (最新) | GPT-4o, Claude 3.5/3.7等 | GPT-4o, Claude等 |
| **価格設定** | **完全従量課金** (API利用料) | 月額 \$20 (定額プランあり) | 月額 \$10 (定額) |
| **フック/拡張性** | **極めて高い** (シェル連携) | 中 (設定ファイルのみ) | 低 (エディタ依存) |
| **自律実行力** | 非常に高い (テスト・ビルド等) | 高い (Composer機能) | 中 (コード生成主体) |

* **Claude Code**は、圧倒的な「自律性（Agent機能）」が特徴です。テストの実行、エラーの自己解決、そして今回ご紹介した「hookを使った自作の自動化」が容易です。
* ただし、**従量課金（API）のため、使いすぎると月に数万円の請求が来るリスク**があります。今回ご紹介した「hookによるコンテキスト最適化」は、**不要なトークン消費を抑え、コスト削減にも直結**します。

## 3. ステマなし！サクラレビューを排除した「本音の口コミ」

SNSや開発者コミュニティ（Zenn, Qiita, X）から、宣伝目的のツイート（サクラ）を徹底排除し、**実際にヘビーユースしているエンジニアの「リアルな本音」**だけを厳選しました。

### 良い評価（リアルなメリット）
> 💡 **「自律性がCursorの比じゃない」**
> 「`npm run test`を勝手に回して、エラーが出たらそのログを見てソースを自己修復して、通るまで繰り返してくれる。このループをCLI内で完結できるのはClaude Codeだけ。一度使うと戻れない。」

> 💡 **「hookでのカスタマイズが無限の可能性」**
> 「プロジェクトごとにルールをgit管理して、hookでClaudeに食わせる運用にしてから、インデントやライブラリ選定のブレがゼロになった。まさに自社専用開発AI。」

### 悪い評価（リアルなデメリット・注意点）
> ⚠️ **「油断するとAPI代が溶ける」**
> 「大規模リポジトリで丸投げタスクを振ったら、裏で何度もファイルを読み直して、1日で50ドル（約7,500円）溶けた。hookを使ってコンテキストを最小限に絞る設計は必須。」

> ⚠️ **「初心者には敷居が高い」**
> 「CLIツールなので、Gitやシェルの知識がないとポテンシャルを発揮できない。あと、たまに破壊的なGit操作を提案してくるので、`git stash`は必須。」
