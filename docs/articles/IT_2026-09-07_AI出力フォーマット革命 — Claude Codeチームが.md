## 1. なぜMarkdownからHTMLなのか？3つの技術的理由

これまで「AIからの回答」といえば、以下のようなMarkdown形式が一般的でした。

```markdown
# タイトル
これは**太字**です。
- リスト1
- リスト2
```

しかし、Claude Code（およびClaudeのWeb UI機能「Artifacts」）の内部では、HTMLや独自のXMLライクなタグ（`<antthinking>`、`<antartifact>`など）が主役となっています。理由は主に3つあります。

### ① パース（解析）エラーの劇的な削減
Markdownは人間にとって書きやすい反面、文法が曖昧です。AIが複雑なコードやUIを出力する際、マークダウンの記号（```など）がネスト（入れ子）になると、システム側で「どこからどこまでがコードブロックなのか」を正確に認識できず、パースエラー（システムエラー）を起こしやすくなります。
一方、**HTML/XMLはタグが厳密に閉じられるため、機械（パーサー）にとって100%正確に処理できます。**

### ② 動的UI（Artifacts）とのシームレスな融合
Claudeの神機能である「Artifacts」は、AIが作成したコードをその場で画面右側にプレビュー表示します。
Markdownでは静的な文書しか表現できませんが、**HTML（+CSS/JS）であれば、ボタンを押したら動くインタラクティブなモックアップやゲームを、AIが生成した直後にその場で実行可能**になります。

### ③ エージェント（Claude Code）による「自己修正」の容易さ
Claude Codeのような自律型AIエージェントは、コードを書き換える際、ファイルの一部をピンポイントで修正します。この際、HTML/XMLで細かく構造化されていると、AIは「どのタグの中身を書き換えればいいか」を正確に把握でき、ファイルの書き換えミスが激減します。
