## 1. そもそも「サブエージェントの統合（Fold）」とは？

従来のAIエージェント設計と、最新の設計手法の違いは以下の通りです。

```
【従来：分離型（Multi-Agent）】
ユーザー ➔ [メイン] ➔ [リサーチAgent] ➔ [ライティングAgent] ➔ [コード作成Agent]
※ 各段階でAPI呼び出しが発生。遅い、高い、文脈が切れる。

【最新：統合型（Folded Main Loop）】
ユーザー ➔ [メインエージェント（超高性能LLM + 適切なツール群）]
※ 1つのループ内でツール呼び出し（Function Calling）として処理。速い、安い、文脈共有。
```

### なぜ今「統合」すべきなのか？
1. **モデル自体の賢さ向上**: Claude 3.5 SonnetやGPT-4oなど、複雑な指示（System Prompt）と複数のToolを一括で扱えるモデルが登場したため。
2. **レイテンシ（遅延）の削減**: エージェント間でバトンタッチする通信時間がゼロになる。
3. **コスト削減**: 重複して送信されるトークン（システムプロンプトや履歴）を大幅カットできる。

### 逆に「サブエージェントに分離すべき」例外パターン
* ツールが多すぎて1つのモデルのContext Windowやツール制限を超えてしまう場合
* ドメイン（専門分野）ごとに全く異なるセキュリティ権限やデータベースを切り分けたい場合
