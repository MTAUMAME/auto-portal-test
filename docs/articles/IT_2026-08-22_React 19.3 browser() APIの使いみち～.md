## 1. React 19.3の目玉「browser() API」とは？

これまで、React Server Components（RSC）の環境下で「ブラウザでのみ実行したい処理（Windowオブジェクトへのアクセス、ローカルストレージの読み書き、Web APIの呼び出しなど）」を行うには、`useEffect`を使うか、コンポーネントを `'use client'` で完全にクライアントコンポーネント化する必要がありました。

しかし、React 19.3で実験的に導入された**`browser()` API**は、**サーバーコンポーネントの記述の中に直接、クライアント（ブラウザ）専用の非同期処理やサイドエフェクトを「安全に」インライン挿入できる**機能です。

### 主要なメリット
* **ハイドレーションエラーの撲滅**: 「サーバーとクライアントでレンダリング結果が異なる」エラーをエレガントに回避。
* **'use client' の削減**: ファイル全体のクライアント化を防ぎ、RSCの恩恵（高速な初期表示）を最大化。
* **宣言的なブラウザ処理**: サーバーサイドレンダリング（SSR）時には無視され、クライアントに到達した瞬間にだけ実行される処理を直感的に書ける。

## 2. FUNSTACK Routerでの「使いみち」と具体例

「FUNSTACK Router」は、RSCをネイティブサポートし、エッジサーバー（Cloudflare Workersなど）での超高速動作を強みとする新世代のフルスタックルーターです。

FUNSTACK Routerと`browser()` APIを組み合わせることで、**「ページ遷移」と「ローカル状態の復元」が劇的にシームレスになります。**

### 具体的なユースケース：ログイン状態によってローカルからダッシュボードを高速描画する

これまでは、ルーティング時に「ローカルストレージにあるトークンを確認してリダイレクトする」際、一瞬のチラつき（Flash of Unstyled Content）が発生しがちでした。

```tsx
// FUNSTACK Router内のRSC（サーバー側で動作）
import { browser } from 'react';
import { redirect } from 'funstack-router';

export default async function DashboardPage() {
  // サーバー側で基本データをフェッチ
  const initialData = await fetchServerData();

  // browser() を使って、クライアント到達時のみローカルキャッシュをマージする
  const localSettings = browser(() => {
    return localStorage.getItem('user-theme') || 'dark';
  });

  return (
    <div className={`dashboard-wrapper ${localSettings}`}>
      <h1>ダッシュボード</h1>
      <p>サーバーデータ: {initialData.status}</p>
    </div>
  );
}
```

このように、サーバーコンポーネントとしての高速性を維持しつつ、**「ブラウザのローカル情報（テーマ、トークン、未保存のドラフトなど）」を直感的にレンダリングに混ぜ込む**ことができます。FUNSTACK Routerの爆速なページ遷移と相まって、ネイティブアプリ並みのUXが実現します。
