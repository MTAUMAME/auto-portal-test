## 1. CSSの救世主 `margin-trim` とは？

これまで、カード型のコンテナやリストを実装する際、最後の子要素（`:last-child`）の `margin-bottom` を手動で打ち消すコードを書いていませんでしたか？

```css
/* これまでの面倒な書き方 */
.container {
  padding: 20px;
}
.card {
  margin-bottom: 15px;
}
/* 最後だけ余白を消す記述が必要だった */
.card:last-child {
  margin-bottom: 0;
}
```

これが、最新の `margin-trim` を使えば、**親要素（コンテナ）に1行追加するだけ**で解決します。

### `margin-trim` の実装例

```css
.container {
  padding: 20px;
  margin-trim: block; /* これだけで、最後の子要素のmargin-bottom（または最初の上マージン）を自動カット！ */
}
.card {
  margin-bottom: 15px; /* すべての要素に一括指定でOK */
}
```

### 指定できる値
*   `none`: トリミングを行わない（デフォルト）
*   `block`: ブロック方向（縦方向）の端にある子要素のマージンをトリミング
*   `inline`: インライン方向（横方向）の端にある子要素のマージンをトリミング

### なぜこれが重要なのか？（AI時代の視点）
ChatGPTやCursorなどのAIエディタに「カード型のUIを作って」と指示した際、従来の複雑な `:last-child` の処理を含めるとコードが長くなり、AIが破綻したコードを出力する原因になります。
`margin-trim` を前提としたプロンプトにすることで、**「親要素に margin-trim を適用して」と指示するだけで、極めて美しくシンプルなコードが生成される**ようになります。

> **⚠️ ブラウザ対応状況（2024年現在）**
> SafariおよびiOS Safariではすでに完全対応。ChromeやEdge（Chromium系）、Firefoxでも順次実装・実験的機能としてフラグが提供されています。実務への完全投入はもう少し先ですが、ポートフォリオや最新モダンWebサイトでは今すぐ使える技術です。
