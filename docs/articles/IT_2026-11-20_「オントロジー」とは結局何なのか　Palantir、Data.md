## 1. そもそも「オントロジー」とは？（3行で超要約）

元々は哲学用語で「存在論」を意味しますが、IT・AI分野におけるオントロジーとは**「データと現実世界の概念・関係性を、コンピューターが理解できるように定義した枠組み」**のことです。

*   **従来のデータ:** 「ユーザーID: 102」「購入履歴: 商品A」という単なるテーブルデータ。
*   **オントロジー:** 「顧客Aは、製品Bを過去に購入し、現在〇〇の課題を抱えているため、サポートチームの行動が必要」という**文脈と意味（メタデータとアクション）の構造化**。

これが作られていると、LLM（大規模言語モデル）や自立型AIエージェントが「次に何をすべきか」を正確に判断できるようになります。

## 2. なぜ4社で「オントロジー」の意味が違うのか？

各社がターゲットにしている「領域」が違うため、オントロジーの定義も異なります。

```
【ビジネス・アクション指向】 Palantir （現実の業務とデータを紐付ける）
【データ・ガバナンス指向】 Databricks / Snowflake （データ基盤とLLMの文脈を統合する）
【物理・空間指向】 NVIDIA （物理法則や3D空間をAIに理解させる）
```

### ① Palantir（Foundry / AIP）：『オペレーショナル・オントロジー』
*   **意味:** データと「企業の現場のアクション（意思決定）」を直結させる仕組み。
*   **特徴:** 単にデータを可視化するだけでなく、「このデータに基づいて、工場Aの生産ラインを止め、配送ルートBに変更する」といったオペレーションの実行までを統合します。

### ② Databricks（Unity Catalog）：『セマンティック＆ガバナンス・オントロジー』
*   **意味:** レイクハウス上のデータ、AIモデル、コードの「意味と権限」を統一管理する仕組み。
*   **特徴:** オープンソース指向。非構造化データ（画像・音声・テキスト）を含め、AIがどのデータを学習し、どう参照すべきかの「文脈（コンテキスト）」を管理します。

### ③ Snowflake（Cortex / Semantic Data Model）：『ビジネス・データ・オントロジー』
*   **意味:** クラウドデータウェアハウス上で、ビジネス指標（売上、顧客データ等）の定義をAIと共有する仕組み。
*   **特徴:** SQLベースの強みを活かし、LLMが誤った集計をしないように「この指標はどう計算されるべきか」というビジネスルール（オントロジー）を厳格に定義します。

### ④ NVIDIA（Omniverse / Modulus）：『フィジカル（物理空間）・オントロジー』
*   **意味:** 3D空間、重力、風量、熱力学などの「物理法則」をデジタルツイン上でAIに理解させる仕組み。
*   **特徴:** 工場の自動化、ロボティクス、自動運転開発向け。現実世界の「物理的な概念とその相互作用」をデータ化しています。
