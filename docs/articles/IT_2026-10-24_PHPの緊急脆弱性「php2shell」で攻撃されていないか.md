# 【緊急対策】PHPの重大脆弱性「php2shell」で攻撃されていないか？サーバーの痕跡チェックと安全なWeb環境の構築ガイド

PHP環境を揺るがす深刻なリモートコード実行（RCE）の脆弱性、通称**「php2shell」**（※CVE-2024-4577等のPHP CGI引数注入攻撃の総称）が拡散しています。

攻撃者にサーバーの制御権を奪われると、**マルウェアの拡散拠点や暗号資産の採掘（マイニング）に悪用される危険性**があります。

まずは「自分のサーバーがすでにやられていないか」をチェックし、適切な防御策を講じましょう。

---

## 1. サーバーに残る「3つの攻撃痕跡」と確認方法

InfraAcademyの記事でも重視されている、攻撃を受けた際（または攻撃試行時）にサーバー内部へ残る典型的な**3つの痕跡**とコマンド例です。

### 痕跡①：アクセスログ内の異常なリクエスト（CGIパラメーターの悪用）
攻撃者は特定のエスケープ文字（`%ad` など）を送り込んでPHPの引数を不正操作します。

*   **確認方法（Linuxコマンド例）：**
    ```bash
    # Apache/Nginxのアクセスログから不正なパラメータパターンを検索
    grep -E "cgi-bin|php-cgi|%ad" /var/log/httpd/access_log
    # または
    grep -E "\-d\+allow_url_include" /var/log/nginx/access.log
    ```
    ※上記のようなリクエストでステータスコードが `200`（成功）になっている場合、突破された可能性があります。

### 痕跡②：`/tmp` や `uploads` ディレクトリ内の不審なファイル作成
Webサーバー権限（`www-data` や `apache`）で書き込みが可能なディレクトリに、Webシェルや実行ファイルが設置されます。

*   **確認方法：**
    ```bash
    # 過去7日以内に作成・更新された不審なPHPファイルや実行ファイルを検索
    find /tmp /var/www/html/wp-content/uploads/ -type f \( -name "*.php" -o -perm /111 \) -mtime -7
    ```

### 痕跡③：不自然な高負荷プロセスと未知の外部通信
乗っ取られたサーバーは、C2サーバー（遠隔操作サーバー）への逆接続（リバースシェル）やマイニングツールを実行させられます。

*   **確認方法：**
    ```bash
    # CPU使用率が高い見慣れないプロセスを確認
    top -c

    # 不審な外部IPアドレスへのESTABLISHED通信を確認
    netstat -antup | grep ESTABLISHED
    # または
    ss -tupn
    ```

## 3. サクラレビューを弾いた「リアルな口コミ・評判」

SNSやエンジニアコミュニティ（X, Qiita, Redditなど）から、プロモーション・サクラと思われる投稿を除外した**本当のユーザーの声**をまとめました。

### ❌ 悪い口コミ（よくある落とし穴）

> **【レンタルサーバー全般】**
> 「旧バージョンのPHPを互換性のために残していたら、そこを突かれてマルウェアを仕込まれた。自動更新をオフにしていると本当に危険。」

> **【Cloudflare（無料プラン）】**
> 「Cloudflareを入れたからと安心していたら、サーバーの直IP（Origin IP）が漏れていて、WAFをバイパスして直接攻撃された。IP制限もしないと意味がない。」

> **【InfraAcademy（学習サイト）】**
> 「教材としては非常に実践的で、ログの追い方がよく分かった。ただ、完全な環境構築の初心者にはコマンドの意味を調べるのが少し難しく感じるかも。」

### ⭕ 良い口コミ（高評価のポイント）

> **【Cloudflare WAF】**
> 「今回のPHPの零日（ゼロデイ）攻撃も、Cloudflareの管理画面でWAFルールが即座に自動適用されていて救われた。Web屋はとりあえず入れておくべき。」

> **【ConoHa VPS】**
> 「脆弱性情報が出た時の公式の注意喚起とセキュリティパッチのあて方のドキュメントが親切。KUSANAGI環境もすぐ組めるのでセキュリティと速度の両立が楽。」

> **【InfraAcademy】**
> 「セキュリティインシデントが起きた時の『ログの追い方』『プロセスの切り分け』が再現環境で体験できるのが良い。教科書を読むだけの学習とはダンチ。」

## 4. ガジェット・AIブログから提案する「収益化（アフィリエイト）動線」

この記事から自然に成果（コンバージョン）へ繋げるための**3つの提案ステップ**です。

### 提案①：即時防御したい人へ「WAF（Cloudflare / サーバーWAF）」の導入推奨
*   **訴求文脈:** 「まずは今すぐ攻撃を防ぐために、DNSを切り替えるだけでPHPの未知の攻撃をエッジでブロックするCloudflareや、標準WAF付きサーバーを導入しましょう。」
*   **ターゲットリンク:** 各種レンタルサーバー（Xサーバー、ConoHaなど）、セキュリティ系SaaSのアフィリエイト。

### 提案②：レガシー環境からの脱却「最新PHPが安全に動くVPS・クラウド」への移行
*   **訴求文脈:** 「古いPHP環境（PHP 7.x系など）を放置するのは自殺行為です。自動バックアップや最新PHP環境への移行がワンクリックでできるVPSへ引っ越しを検討してください。」
*   **ターゲットリンク:** `ConoHa VPS`、`さくらのVPS`、`シン・レンタルサーバー` などのA8.net/afb案件。

### 提案③：インフラ・セキュリティスキルを高めたい人へ「InfraAcademy」等でのリスキリング
*   **訴求文脈:** 「攻撃の痕跡（ログ）を見てもピンと来なかった方は、インフラ知識のアップデートが必要です。『InfraAcademy』のような実践型サイトで、インシデント対応ができるエンジニアを目指しましょう。」
*   **ターゲットリンク:** `InfraAcademy`（アフィリエイト提携がある場合）や `Udemy`（Linux/セキュリティ講座）、ITスクール案件。

## 5. まとめ：攻撃される前にやるべきこと

1.  **アクセスログと `/tmp` ディレクトリを今すぐ確認する**
2.  **PHPのバージョンを最新版にアップデートする**
3.  **WAFを導入し、サーバー手前で攻撃リクエストを弾く**
