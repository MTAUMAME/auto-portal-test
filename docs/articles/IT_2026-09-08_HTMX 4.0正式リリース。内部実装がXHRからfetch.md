## 1. HTMX 4.0の主なアップデート内容

今回のアップデートにおける最大のトピックは以下の3点です。

### ① 内部実装が「XHR」から「fetch API」に移行 ➜ Streaming HTMLが可能に！
従来のHTMXは、歴史的な経緯から非同期通信に`XMLHttpRequest (XHR)`を使用していました。
HTMX 4.0では、これがモダンな**`fetch API`**へと完全に移行。これにより、以下の恩恵を受けられるようになりました。

* **Streaming HTML（ストリーミング応答）の実現**: サーバーから分割して送られてくるHTMLデータを、受信しながらリアルタイムに画面に描画・反映できるようになりました。AIのチャットUI（ChatGPTのような文字がパラパラ出てくるUI）や、重いデータのローディング表示が劇的にスムーズになります。
* **モダンブラウザへの最適化**: コードベースが軽量化され、ブラウザの通信パフォーマンスが向上しました。

### ② 属性がデフォルトで子要素に継承されないように変更（Breaking Change）
これまでのHTMXでは、親要素に定義した`hx-target`や`hx-select`などの属性が自動的に子要素に継承されていました。これが原因で「意図しない要素が書き換わってしまう」というバグに悩まされる開発者が多く存在しました。

HTMX 4.0では、**「属性はデフォルトで子要素に継承されない」**仕様に変更されました。
* **メリット**: コードの可読性が向上し、意図しない挙動（サイドエフェクト）が激減します。
* **注意点**: 旧バージョン（v1.x/v2.x等）から移行する場合、明示的に継承を指定する、もしくは構造を見直す必要があります。

## 2. ライバル技術との「性能・コスト」比較

「本当にReactやNext.jsから移行する価値はあるのか？」
開発コスト（価格的な観点）と、実際の動作パフォーマンス（性能）を、他の選択肢と比較しました。

| 比較項目 | **HTMX 4.0** (NEW) | **React / Next.js (App Router)** | **Alpine.js** |
| :--- | :--- | :--- | :--- |
| **初期導入・ライセンス費用** | **完全無料** (オープンソース) | **完全無料** (オープンソース) | **完全無料** (オープンソース) |
| **JSバンドルサイズ** | **極小 (約14KB)** | 肥大化しやすい (数百KB〜) | 軽量 (約15KB) |
| **学習コスト（実質的な人件費）** | **極めて低い** (HTMLの知識のみ) | **極めて高い** (Hooks, SSR, 状態管理) | 低い (Vue風の直感的な記述) |
| **通信方式** | **fetch API** (Streaming対応) | Fetch / WebSockets / gRPCなど | Fetch / Axios等と組み合わせ |
| **サーバー負荷** | HTMLを返すため中程度 (キャッシュ有効) | SSR/ISRの処理で高負荷になりがち | クライアント側で処理するため低 |
| **UX（ユーザー体験）** | 爆速（JSのパース・実行がほぼ不要） | リッチだが、初期読み込みにラグあり | 非常にスムーズ |

### 結論：どちらを選ぶべき？
* **HTMX 4.0が最適**: 「管理画面」「CRUD系システム」「シンプルなECサイト」「AIチャットアプリ」。重いJSをブラウザにダウンロードさせたくない、SEOと初期表示速度を最優先したい場合。
* **React/Next.jsが最適**: 「Figmaのような超リッチなインタラクティブアプリ」「オフラインファーストのPWA」。
