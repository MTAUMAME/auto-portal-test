## 1. Fallowとは？：静的（無料）と動的（有料）のハイブリッド解析

GitHubで公開されている『Fallow』は、TS/JSプロジェクトの「不健康なコード」を特定するためのRust製ツールです。
最大の特徴は、**「無料の静的解析（Static）」**と**「有料の動的解析（Runtime）」**の2つのレイヤーを持っている点です。

```
Fallowの構成
├── 【無料】静的レイヤー（Static Layer）: コードを読まずに構造や不要箇所を高速分析
└── 【有料】動的レイヤー（Runtime Layer）: 実際に動いているアプリの死に筋コードを特定
```

### ① 【完全無料】静的レイヤー（Static Layer）
ローカルやCI/CD環境で実行。コードを実行することなく、以下の問題を瞬時に検出します。
*   **Unused Code（未使用コード）:** どこからもインポートされていないファイルや関数。
*   **Duplication（コードの重複）:** コピペされた冗長なコード。
*   **Circular Deps（循環参照）:** モジュールAとBが互いに依存し合うバグの温床。
*   **Complexity Hotspots（複雑度の高い箇所）:** 認知負荷が高く、リファクタリングが必要な場所。
*   **Architecture Boundaries（設計境界の違反）:** ディレクトリ間の不正な依存（例: プレゼンテーション層がデータ層を直接呼ぶなど）。

### ② 【有料】動的レイヤー（Runtime Layer）
本番環境で「実際にコードが通ったルート」を監視します。
*   **Hot-path review（ホットパスの特定）:** 頻繁に実行されるコード。ここを最適化すればコスパ良く高速化できます。
*   **Cold-path deletion（コールドパスの削除）:** 「コード上は存在するが、本番環境で1回も実行されていないコード」を安全に削除できます。

## 2. 性能・価格比較：既存ツールと何が違う？

TS/JSの解析ツールは他にもありますが、Fallowは何が優れているのでしょうか？
代表的なツール（Knip, ESLint, SonarQube, Datadog）と比較しました。

| 比較項目 | **Fallow** | **Knip** | **ESLint / Biome** | **SonarQube** | **Datadog / Sentry** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **主な用途** | コードベース分析 & 動的監視 | 未使用コード検出 | 静的リント（構文チェック） | 統合コード品質管理 | アプリ監視 (APM) |
| **解析速度** | 🚀 **極めて高速** (Rust製) | 普通 (Node.js製) | 普通 | 低速 (Java製等) | N/A (本番監視) |
| **循環参照検出**| **あり** | なし（別ツールが必要）| プラグインで可能 | あり | なし |
| **本番環境の追跡**| **あり（有料プラン）** | なし | なし | なし | あり（ただしコード削除用ではない） |
| **料金** | **基本無料** / 動的監視は有料 | 完全無料 | 完全無料 | 有料（一部無料） | 高額（従量課金） |

### Fallowの強み：
Knipなどの優れた静的解析ツールはありますが、Node.js製のため大規模リポジトリでは解析に時間がかかります。**FallowはRust製のため、数万行のコードも一瞬でスキャン完了します。**
また、「本当に本番で使われていないか」を監視する動的レイヤーを持つツールは他にほぼありません。

## 4. 総評：Fallowは導入すべきか？

*   **個人開発・小規模プロジェクト:**
    まずは**無料の静的レイヤー（Static Layer）を導入するだけで十分な恩恵**が得られます。ビルド速度向上とコード整理に役立ちます。
*   **中規模〜大規模・レガシープロジェクト:**
    長年運用されて誰も触れない「秘伝のタレ」化したコードがある場合、**有料の動的レイヤーを数ヶ月契約し、未使用コードを一掃する**価値は十二分にあります。
