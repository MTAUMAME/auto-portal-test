## 1. Googleが提唱する「SKILL.state」とは？

一言で言えば、**「プロンプトを感覚的な『文章』から、構造化された『プログラム（関数）』に進化させるアプローチ」**です。

従来のプロンプトは「〜をしてください」という命令文（自然言語）でしたが、「SKILL.state」では以下の要素をカプセル化して定義します。

*   **SKILL（スキル）：** AIに実行させたい特定の機能（例：翻訳、要約、コード生成）。入力と出力の「型（Type）」を厳密に定義する。
*   **state（状態）：** 処理の進行状況や変数を保持する。

### 従来のプロンプトと「SKILL.state」の違い（イメージ）

| 項目 | 従来のプロンプト | SKILL.state導入プロンプト |
| :--- | :--- | :--- |
| **アプローチ** | 「〜を考慮して、いい感じに出力して」 | 「入力：[テキスト], 処理：[要約], 出力型：[JSON: {title, summary}]」 |
| **出力の安定性** | 低い（毎回結果が変わる） | 極めて高い（常に同じ構造で出力） |
| **エラー率** | 高い（指示を忘れる「プロンプト崩れ」が発生） | 極めて低い（「型」に縛られているため） |
| **アプリ連携** | 困難（テキスト解析が必要） | 容易（APIや外部システムとノーコードで繋がる） |
