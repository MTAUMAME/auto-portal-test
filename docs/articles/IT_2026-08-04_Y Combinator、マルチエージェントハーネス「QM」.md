## 1. マルチエージェントハーネス「QM」とは？

「QM（Queue Manager / Workspaces）」は、組織内のマルチエージェントシステムを安全かつスケーラブルに運用するための**オープンソース・ハーネス（制御・管理基盤）**です。

### 主な特徴とメリット
*   **個別サンドボックスの自動生成**: Slackのチャンネルごと、あるいはユーザーごとに、完全に分離された実行環境（コンテナ）を即座に立ち上げます。
*   **強固なセキュリティ**: エージェントが勝手に組織の機密ファイルにアクセスしたり、悪意のあるコードを実行したりするリスクを最小限に抑えます。
*   **マルチエージェントの協調**: 複数の異なるAIエージェント（LLM）を束ね、タスクをキュー管理しながら並列処理できます。

これまで企業が自社専用の安全なAI実行環境を作ろうとすると、インフラエンジニアが数週間かけて構築する必要がありましたが、QMを使えばその手間を大幅に削減できます。

## 2. 競合ツールとの「価格・性能」比較

「QM」と、現在人気のAIエージェントフレームワーク（LangGraph、CrewAI）を比較してみましょう。

| 比較項目 | **QM (Queue Manager)** | **LangGraph** | **CrewAI** |
| :--- | :--- | :--- | :--- |
| **開発元** | Y Combinator支援プロジェクト | LangChain社 | CrewAI Inc. |
| **主な用途** | 組織内での安全なエージェント**インフラ管理** | 複雑なエージェントの**ロジック・循環グラフ構築** | 直感的な**役割分担型エージェント**の作成 |
| **ライセンス / 価格** | **オープンソース (無料)** / セルフホスト | OSS（一部クラウド版LangGraph Cloudは有料） | OSS（一部有料プランあり） |
| **環境分離（サンドボックス）**| **極めて高い**（ユーザー/チャンネル単位で自動分離） | 開発者が自前でDocker等を用意する必要あり | 自前で環境構築が必要 |
| **難易度** | インフラ（Docker/Kubernetes）の知識が必要 | Python/JavaScriptの高度なプログラミング知識 | 比較的初心者向け（ノーコード的にも動かせる） |

### 結論：どれを選ぶべき？
*   **QMが向いている人**: 企業内のSlackやTeamsで、安全にAIエージェントを実稼働させたいインフラ担当者・開発リーダー。
*   **LangGraph/CrewAIが向いている人**: まずはローカル環境で、AI同士に複雑なディスカッションをさせたい個人開発者。
