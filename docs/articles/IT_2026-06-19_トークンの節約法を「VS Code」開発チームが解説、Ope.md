## 1. VS Code開発チームが明かした「トークン節約・遅延削減」3つのコア技術

VS Codeのチャット機能やGitHub Copilotは、裏側でOpenAIやAnthropicのLLMを呼び出しています。開発チームが「コストと遅延」を最小化するために実装したアプローチは主に以下の3つです。

### ① プロンプトキャッシュ（Prompt Caching）の最大活用
開発において、システムプロンプトや、プロジェクトの「 codebase（コードベース）の定義」など、**毎回のチャットで重複して送信されるデータ（コンテキスト）**は非常に多くなります。
VS Codeチームは、これらをAPI側の「キャッシュ」に保持させることで、毎回ゼロからLLMに読み込ませるのを防ぎました。これにより、**処理速度が最大2倍以上高速化し、コストも劇的に削減**されました。

### ② コンテキストの遅延読み込み（Lazy Loading）
ユーザーがチャットを入力した際、最初からすべてのファイル情報をLLMに送りつけるのではなく、**「今本当に必要な情報だけ」を段階的に読み込む（遅延読み込み）**仕組みを導入しました。これにより、不要なトークン消費を徹底的にカットしています。

### ③ 差分（Diff）送信と賢いコンテキスト削減
ソースコード全体を送信するのではなく、**「直近で編集された差分（Diff）」だけを抽出してLLMに送信**します。さらに、トークン上限（コンテキストウィンドウ）に達しそうな場合は、古い会話履歴や重要度の低いファイル情報を自動で間引くアルゴリズムを導入しています。

## 2. OpenAI vs Anthropic「プロンプトキャッシュ」徹底比較

プロンプトキャッシュは、現在の2大AI企業である**OpenAI（GPT-4oなど）**と**Anthropic（Claude 3.5 Sonnetなど）**の両方でサポートされていますが、その仕様や料金体系には大きな違いがあります。

| 比較項目 | OpenAI (GPT-4o) | Anthropic (Claude 3.5 Sonnet) |
| :--- | :--- | :--- |
| **キャッシュ対象モデル** | GPT-4o, GPT-4o-mini 等 | Claude 3.5 Sonnet, Claude 3 Opus 等 |
| **適用の自動化** | **完全自動**（128kトークン以上のリクエストで自動適用） | **手動指定が必要**（APIリクエスト時にキャッシュポイントを設定） |
| **キャッシュ有効期限 (TTL)** | 通常 5分〜1時間（アクティビティによる） | 5分（リクエストごとにリセット） |
| **書き込み料金 (Cache Write)** | 通常のインプット料金と同等 | 通常のインプット料金の**約1.25倍** |
| **読み込み料金 (Cache Hit)** | 通常のインプット料金の**50%OFF（半額）** | 通常のインプット料金の**90%OFF（1/10）** |
| **性能・レイテンシ削減効果** | 非常に高速。開発者が意識せずとも恩恵を受けられる | 巨大なソースコードを読み込ませた際の**爆速化＆超低コスト化**が顕著 |

### どっちを選ぶべき？
* **手軽さと自動化重視なら「OpenAI」**：何も設定しなくても自動でキャッシュが効き、料金が半額になります。
* **圧倒的なコスト削減と高精度なコーディングなら「Anthropic (Claude)」**：事前のキャッシュ指定が必要ですが、**ヒット時の料金が1/10**になるため、大規模なソースコードを何度も参照するコーディングアシスタント開発ではAnthropicが圧倒的に有利です。
