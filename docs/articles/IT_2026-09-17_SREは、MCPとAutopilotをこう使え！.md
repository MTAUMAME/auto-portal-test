## そもそも「MCP」と「Autopilot」って何？

SREの現場において、この2つが組み合わさることで**「指示を出すだけで、AIがインフラの調査から修正PRの作成まで完結する」**という夢の環境が実現します。

```
[SRE (指示)] ──> [Autopilot (司令塔)] ──(MCP経由)──> [AWS/K8s/DB/GitHub (実作業)]
```

*   **MCP（Model Context Protocol）とは？**
    AI（LLM）と、外部のデータソースやツール（DB、GitHub、ローカルファイル、Kubernetes等）を安全に接続するためのオープンな規格。これにより、AIが「今起きているリアルタイムのシステム情報」に直接アクセスできるようになります。
*   **Autopilot（自律エージェント）とは？**
    「〇〇を修正しておいて」という1つの指示に対し、AIが自分で思考し、ファイルを跨いで複数ステップの修正を実行、完了まで自律的に行う機能（CursorのComposerやGitHub Copilot Workspaceなど）。

## SREはこう使え！MCP×Autopilotの極限ユースケース3選

### 1. 障害発生時のリアルタイムログ解析＆パッチ作成
*   **MCP接続先:** `Kubernetes MCP Server` + `Elasticsearch MCP Server`
*   **Autopilotへの指示:** 「〇〇サービスで500エラーが多発している。ログを解析して原因を特定し、修正のためのTerraform（またはマニフェスト）の修正PRを作って」
*   **挙動:** AIが自らMCP経由でログを取得・解析。原因がメモリリークだと判断すると、自律的にレプリカ数やメモリ制限を変更するPRを作成します。

### 2. 「秘伝のタレ」化したTerraformのコードクレンジング
*   **MCP接続先:** `Local File System` + `GitHub`
*   **Autopilotへの指示:** 「現在のインフラ構成と最新のTerraformベストプラクティスを比較し、非推奨の記法やセキュリティリスクがある箇所をすべて修正して」
*   **挙動:** 複数ファイルにまたがるコードを自動でスキャンし、一括でリファクタリング。テストが通るまで自律的にデバッグを繰り返します。

### 3. 社内Wiki（Notion/SaaSes）からの障害対応ナレッジ自動検索
*   **MCP接続先:** `Notion MCP Server` + `Slack MCP Server`
*   **Autopilotへの指示:** 「〇〇のDB接続エラーについて、過去のNotion障害報告書から類似ケースを探し、Slackにスレッドで対策をまとめて」
*   **挙動:** ナレッジを探索し、適切な手順書をベースにした対策を自動生成します。
