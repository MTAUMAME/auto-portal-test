## 1. Nginxで稀に起きる502の真犯人「Keepalive」とは？

### 502 Bad Gatewayが「稀に」起きるメカニズム

通常、Nginx（リバースプロキシ）はクライアントからのリクエストを、奥にあるアプリケーションサーバー（Node.js, Python/Gunicorn, PHP-FPMなど）やAWSのALB（Application Load Balancer）に転送します。

この際、パフォーマンス向上のためにコネクションを使い回す**「Keepalive接続」**を利用するのが一般的です。

しかし、ここに**「タイムアウトの罠」**が潜んでいます。

```
[クライアント] ──> [ Nginx ] ──(Keepalive接続)──> [ バックエンド ]
                                                   │
                                            (一定時間無風で...)
                                                   │
                                            [バックエンドが切断開始！]
                                                   │
                [ Nginxがパケット送信！] ──(衝突)───┤ (FIN)
                                                   ▼
                                        【 502 Bad Gateway 】
```

1. **無風状態：** しばらくリクエストがない時間が続く。
2. **バックエンドの限界：** バックエンド側（またはロードバランサー）のKeepaliveタイムアウト（例：60秒）が先に到達し、コネクションを閉じようとする（FINパケットを送信）。
3. **タイミングの衝突（レースコンディション）：** まったく同じ瞬間に、Nginxが新しいリクエストを受け取り、使い回そうとしたコネクションでバックエンドにデータを送信してしまう。
4. **エラー発生：** 閉じかかっているコネクションにデータを送られたバックエンドは「もう閉じたよ（RST）」と返し、Nginxは「通信相手が異常終了した」と判断して**502 Bad Gateway**を返します。

これが、アクセスが少ない時間帯や、定期的なバッチ処理の合間などに「稀に502が発生する」原因です。

## 2. 解決策：設定ファイルを1行見直すだけ！

対策は非常にシンプルです。
**「Nginx側のKeepaliveタイムアウト値を、バックエンド（Upstream）のタイムアウト値よりも確実に短く設定する」**ことです。

Nginx側が先に自発的にコネクションを切断するようにしておけば、この衝突は発生しません。

### Nginxの設定例（nginx.conf）

```nginx
http {
    # クライアントとの接続
    keepalive_timeout 65;

    upstream backend_servers {
        server 127.0.0.1:8080;
        keepalive 32; # Keepaliveを有効化
    }

    server {
        listen 80;
        location / {
            proxy_pass http://backend_servers;
            proxy_http_version 1.1;
            proxy_set_header Connection ""; # Keepaliveを有効にするために必要
            
            # ★ここが重要：バックエンドがAWS ALB(デフォルト60秒)の場合、
            # Nginx側の読込タイムアウトなどを適切に設定
            proxy_connect_timeout 60s;
            proxy_read_timeout 60s;
        }
    }
}
```

*   **AWS ALB（デフォルト120秒または60秒）を使う場合：** Nginx側の `keepalive_timeout` をそれより数秒〜数十秒短く設定します。
*   **Node.js / Gunicorn等の場合：** アプリ側の `keepalive` 設定（例：Gunicornの `--keep-alive`）を確認し、Nginx側の設定値とズレがないか、Nginx側が先に切るよう調整します。
