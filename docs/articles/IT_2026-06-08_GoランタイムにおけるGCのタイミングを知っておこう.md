# 【Goランタイム】パフォーマンスの鍵！GC（ガベージコレクション）の起動タイミングを徹底理解する

Go言語は、高い並行処理性能とシンプルな文法で、現代のAI Webアプリケーションのバックエンドに最適な言語です。しかし、高負荷なAI APIのハンドリングや大量のデータ処理を行う際、**「GC（ガベージコレクション）による一時停止（Stop The World: STW）」**がボトルネックになることがあります。

GoのGCは非常に優秀（3色マーク＆スイープ法、目標STWは1ミリ秒未満）ですが、その**起動タイミング**を知っておくことで、メモリ効率とレスポンス速度を極限まで高めることができます。

## 1. GoのGCが起動する「3つのタイミング」

Goランタイムにおいて、GCがトリガーされる瞬間は主に以下の3つです。

| 起動トリガー | 概要 | 調整方法 |
| :--- | :--- | :--- |
| **1. ヒープ成長率（GOGC）** | 前回GC終了時のライブメモリに対し、設定された割合（デフォルト100%）だけヒープが増加した時。 | 環境変数 `GOGC` で調整（例: `GOGC=200` でGC頻度を半分に） |
| **2. 2分間の時間経過** | 前回のGCから2分間、一度もGCが起動しなかった場合、ランタイムが強制的にGCを実行。 | システムがアイドル状態の時のメモリ解放用 |
| **3. メモリ限界値（SetMemoryLimit）** | Go 1.19から導入。設定したメモリ上限に達しそうになると、GCが積極的に介入する。 | `debug.SetMemoryLimit` で設定（OOM（メモリ不足）対策に最強） |

### 💡 プロの知恵：AI開発でGoを使うなら `SetMemoryLimit` は必須！
LLM（大規模言語モデル）のAPIを叩くGoアプリケーションや、ローカルで軽量AIを動かす場合、メモリ消費の予測が困難です。`SetMemoryLimit` を設定しておくことで、コンテナ環境（KubernetesやCloud Runなど）での**OOM Killerによる強制終了を劇的に減らす**ことができます。
