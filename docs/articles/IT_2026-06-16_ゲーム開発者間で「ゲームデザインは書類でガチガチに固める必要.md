# ゲーム開発者を二分する「800ページの仕様書」論争とは？

https://automaton-media.com/articles/newsjp/20241021-315124/
*※元記事：AUTOMATON「ゲーム開発者間で『ゲームデザインは書類でガチガチに固める必要あるか』巡って議論沸騰。ヒット作の“800ページ超えデザインドキュメント”、真似るべきか否か」*

### 議論の背景
*   **仕様書ガチガチ派（大規模開発・パブリッシャー向け）：**
    *   大人数のチームでビジョンを共有するためには、詳細な仕様書（GDD）が不可欠。
    *   『バルダーズ・ゲート3』のような超大作では、複雑な分岐や設定をドキュメント化しないと崩壊する。
*   **アジャイル・プロトタイプ派（インディー・中規模向け）：**
    *   「動くコードが仕様書である」。紙の書類は作った瞬間から古くなる。
    *   文字を読むより、実際にプレイして面白いかどうか（プロトタイプ）で判断すべき。

### 【AI専門ブログの視点】AI時代における仕様書の「新しい価値」
実は、AI（LLM：大規模言語モデル）の台頭により、この議論に新たなパラダイムシフトが起きています。
現代のゲーム開発において、**詳細な仕様書は「AI（GitHub CopilotやClaude 3.5 Sonnetなど）に食わせるための、超高精度なプロンプト」として機能する**のです。

仕様書がガチガチに固まっていれば、AIにそれを読み込ませるだけで、アセットの自動生成やコードのモックアップ作成が数秒で完了します。つまり、**「仕様書をしっかり書くこと」＝「プロトタイプを爆速で作ること」に直結する時代**が来ています。
