## 1. JSONに潜む「実装差異」の罠とは？

RFC 8259で標準化されているJSONですが、パース（解析）を行うプログラミング言語やライブラリによって、その挙動には微妙な、しかし致命的な差異が存在します。

### 罠①：重複キーの扱い
```json
{
  "username": "alice",
  "username": "bob"
}
```
上記のJSONをパースした際、エラーを吐くか、先勝（alice）か、後勝（bob）かは環境に依存します。
*   **JavaScript (`JSON.parse`)**: 後勝ち（`bob` に上書き）
*   **Python (`json.loads`)**: 後勝ち（`bob` に上書き）
*   **Go (`encoding/json`)**: 後勝ち（ただし、`DisallowUnknownFields`などの厳格オプションや外部パーサーによってはエラーにできる）

### 罠②：巨大な数値（精度欠損）
```json
{
  "id": 9007199254740993
}
```
JavaScript（Node.jsなど）でこれをそのままパースすると、倍精度浮動小数点数（IEEE 754）の限界を超え、`9007199254740992` に丸められてしまいます。セキュリティトークンや決済IDなどでこれが起きると大惨事になります。

### 主要言語・パーサーの挙動比較表

| 項目 | JavaScript (`JSON.parse`) | Python (`json`) | Go (`encoding/json`) | Rust (`serde_json`) |
| :--- | :--- | :--- | :--- | :--- |
| **重複キー** | 後勝ち (エラーなし) | 後勝ち (エラーなし) | 後勝ち (構造体マッピング時は注意) | デフォルトは後勝ち (設定でエラー可) |
| **巨大整数 (>2^53 - 1)** | 精度欠損 (丸められる) | 任意精度で保持可能 | `json.Number`指定で保持可能 | `u64`/`i64`/`u128`で厳密に保持 |
| **末尾カンマ** | 構文エラー | 構文エラー | 構文エラー | 構文エラー |
