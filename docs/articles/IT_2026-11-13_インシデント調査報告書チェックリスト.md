# 【保存版】インシデント調査報告書チェックリスト

まずは、報告書に絶対に含めるべき項目を5つのステップにまとめたチェックリストです。AI生成ツールに入力するプロンプトのテンプレートとしてもそのまま活用できます。

### 1. 初動対応と概要（Overview）
* [ ] **発生日時・検知日時**: インシデントの発生・検知・Primary対応のタイムライン
* [ ] **影響範囲の特定**: 対象機器（IP/MAC）、アカウント、データ種別、影響ユーザー数
* [ ] **重大度の判定**: 暫定的なステータス（高・中・低）の定義と根拠
* [ ] **一次対応（封じ込め）**: ネットワーク遮断、アカウント停止などの実施内容

### 2. 原因究明とフォレンジック調査（Investigation）
* [ ] **侵入経路（ベクター）**: メール、VPN、Web脆弱性、内部不正など
* [ ] **マルウェア/攻撃の特定**: マルウェア名、ハッシュ値、C2サーバーIP、使用コマンド
* [ ] **ログの保全と分析**: EDR、SIEM、プロキシ、FW等のログ確認結果
* [ ] **被害データの詳細**: 漏洩・暗号化・改ざんされたデータの具体的内容

### 3. 被害影響とリスク評価（Assessment）
* [ ] **業務への影響**: システム停止時間、サービス提供への影響
* [ ] **二次被害のリスク**: 顧客情報漏洩、他システムへの横展開（ラテラルムーブメント）の可能性
* [ ] **法的・規制上のリスク**: 個人情報保護委員会への報告要否、GDPR等の対象か

### 4. 再発防止策と恒久対応（Remediation）
* [ ] **短期的対策（即座に実施）**: 脆弱性パッチ適用、パスワード強制リセットなど
* [ ] **中長期的対策（体制・システム強化）**: ネットワーク隔離、AI監視ツールの導入、運用ルールの見直し

### 5. 報告・開示（Communication）
* [ ] **ステークホルダーへの報告**: 役員、社内通知、顧客へのプレスリリース
* [ ] **監督官庁・警察への届出**: 個人情報保護委員会、警察、JPCERT/CCへの報告状況
