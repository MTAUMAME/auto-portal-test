## 1. Qiitaの人気記事に学ぶ！Docker環境をガチで軽量化する「3つの鉄板設定」

まずは、Dockerが重くなる原因（メモリ喰い・ストレージ圧迫）をソフトウェア側から解決する、Qiita記事の超重要ポイントを3つに凝縮してご紹介します。

### ① 【ディスク削減】不要なイメージ・コンテナの一括削除
Dockerは古いイメージや不要なボリュームを自動で削除してくれません。以下のコマンドを定期的に実行（またはエイリアス登録）しましょう。

```bash
# 未使用のコンテナ、イメージ、ネットワーク、キャッシュを一括削除
docker system prune -a --volumes
```
これだけで数十GBの空き容量が復活することも珍しくありません。

### ② 【Windows/WSL2向け】`.wslconfig`でのメモリ制限
WindowsでDocker Desktop（WSL2）を使う場合、**デフォルトではPCの物理メモリの最大50%〜80%をWSL2が占有**してしまいます。
`C:\Users\<ユーザー名>\.wslconfig` ファイルを作成し、以下のように制限をかけましょう。

```ini
[wsl2]
memory=8GB   # PCの搭載メモリに応じて4GB〜12GB程度に制限
processors=4 # CPUコア数の割り当て制限
```

### ③ 【ビルド高速化】マルチステージビルドの徹底
Dockerfile内で、ビルド用と実行用のステージを分ける「マルチステージビルド」を採用することで、最終的なイメージサイズを数GBから数十MBにまで軽量化できます。
