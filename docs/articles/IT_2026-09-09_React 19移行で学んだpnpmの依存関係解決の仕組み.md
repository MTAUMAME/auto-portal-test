# React 19移行で激突した「pnpm」の壁。依存関係解決の仕組みと突破口

## 1. なぜReact 19移行でpnpmが牙をむくのか？

React 19の正式リリースに伴い、多くの開発者がアップグレードを進めています。しかし、パッケージマネージャーに**pnpm**を採用しているプロジェクトでは、高確率で以下のようなエラーに遭遇します。

```bash
ERR_PNPM_PEER_DEP_ISSUES  Unmet peer dependencies...
```

### npm/Yarnとpnpmの「構造の違い」
この問題の本質は、pnpm独自の**「コンテンツアドレスキャッシュ（Content-Addressable Store）」**と**「非フラットな `node_modules`（シンボリックリンク構造）」**にあります。

```
【従来のnpm (フラット構造)】
node_modules/
  ├── react (v19)
  ├── library-a (React 18用)
  └── react-dom (v19)  ← library-aがこれを勝手に参照できてしまい、実行時エラーになる

【pnpm (厳格なリンク構造)】
node_modules/
  ├── .pnpm/
  │    └── library-a@1.0.0_react@18.0.0/ (依存が厳格に分離)
  └── library-a (シンボリックリンク)
```

*   **npm/Yarn（v1以降）:** `node_modules`をフラットに展開するため、多少の依存関係の不整合（Peer Dependenciesの不一致）があっても「なんとなく」動いてしまいます（これが「幽霊依存関係」の原因になります）。
*   **pnpm:** 依存関係のグラフを厳格に再現します。ライブラリAが「React 18」を要求しているのに、プロジェクトに「React 19」が入っている場合、**ビルドすら通さない強固なセキュリティ**を発揮します。

### React 19移行時の解決策：`pnpm.overrides`
React 19に未対応のサードパーティ製ライブラリがある場合、`package.json`に以下を追記して強制的に解決します。

```json
{
  "pnpm": {
    "overrides": {
      "react": "rc",
      "react-dom": "rc"
    },
    "peerDependencyRules": {
      "ignoreMissing": [
        "react",
        "react-dom"
      ]
    }
  }
}
```
