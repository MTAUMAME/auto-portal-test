今回は、海外のトレンド記事をベースに、**SSH・tmux・LaunchAgentを使って、メインPCから安全かつ快適にアクセスできる「Claude Code専用エージェント環境」の構築方法**と、そのための最適なハードウェア選びを徹底解説します！

## 1. なぜ「余ったMac」が最強のAIエージェント機になるのか？

海外の元記事で提案されているシステムモデルは非常にシンプルかつ合理的です。

```
[メインのMac/Windows]
      │ (SSH接続)
      ▼
[余ったMac (Agent専用機)]
  └ 1. tmux（接続が切れてもAIはバックグラウンドで動き続ける）
  └ 2. LaunchAgent（起動時に自動で環境構築・待機）
  └ 3. 完全に隔離されたローカル環境（ファイル破壊リスクをメイン機に持ち込まない）
```

### この構成のメリット：
1. **セキュリティと安心感：** AIに全てのファイルシステムへのアクセス権（Full Disk Access）を与えても、メインPCには一切影響がありません。
2. **24時間タスクの実行：** 重いリファクタリングやテストの自動化をAIに任せ、メインPCの接続を切って（ノートPCを閉じて）も、裏でMac miniなどが処理を続行してくれます。
3. **ローカルリソースの節約：** メイン機のメモリやCPUを一切消費しません。

## 2. 構築プロセスの概要（海外記事の知恵）

具体的な設定ステップは以下の通りです。

### ① ターゲットMacのSSH有効化
余っているMacの「システム設定」＞「一般」＞「共有」から「リモートログイン」をONにします。

### ② tmuxの導入
メインPCからSSHで接続した後、セッションが切れてもAIのタスクが止まらないように `tmux` を導入します。
```bash
brew install tmux
```
これで、`tmux new -s claude-agent` を起動してその中で `claude` を動かせば、SSHの接続を切ってもAIは裏で動き続けます。

### ③ LaunchAgentによる自動化
Macの起動時に自動でエージェント環境の準備や特定のパスを通すため、`~/Library/LaunchAgents/` にカスタムの plist ファイルを配置。
これにより、電源が入っていればいつでも「メイン機から一発でClaude Code環境にアクセス」が可能になります。
