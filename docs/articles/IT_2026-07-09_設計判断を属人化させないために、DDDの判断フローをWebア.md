## 1. なぜDDDの判断は属人化するのか？

DDDが素晴らしい手法であることは誰もが認めるところですが、実践において以下の問題が頻発します。

1. **「文脈（コンテキスト）」による解釈のズレ**
2. **公式本（エリック・エヴァンス本）が難解すぎて、メンバー間で解釈が異なる**
3. **「声の大きいエンジニア」の意見が正義になってしまう**

これらを解決するために、**「YES/NOのフローチャート」に加えて「最新AIによる対話型レビュー」を融合したWebアプリ**を作成しました。

### 開発した「DDD判断フローWebアプリ」の概要
* **フロントエンド**: Next.js (App Router) + Tailwind CSS (Vercelデプロイ)
* **バックエンド/AI**: Supabase + OpenAI API (GPT-4o) / Anthropic API (Claude 3.5 Sonnet)
* **機能**: 
  1. 画面上の質問（「一意な識別子は必要か？」「状態は変化するか？」等）に答えるだけで、推奨されるDDDパターンを判定。
  2. 判定に迷う部分は、AIチャットにコードや仕様を貼り付けるだけで、DDDの原則に基づいた設計アドバイスをリアルタイムで返答。
